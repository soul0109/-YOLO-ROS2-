## 起步为什么慢（先记着，十轮后再优化）

每轮脚本故意串行：

1. `clear_nav`：等 idle / cmd 静默（常 ≈10s，status 未观测也要 hold）
2. `delete_entity` + `spawn`：重生落地
3. `initialpose` + `wait_for_nav_ready`：costmap/AMCL/TF
4. `patrol` 内 `wait_ready`：本节点 TF buffer 再灌一桶

所以肉眼「停很久才走」多半是**协议等待**，不是车坏了。可优化点（**十轮后**再动）：缩短 clear hold、spawn 后并行就绪、复用 TF listener、可选 skip-respawn 调试模式。
