## 0. 硬钉死（读完再采）

| # | 规则 |
|---|---|
| 1 | **检测类 ≠ PASS/FAIL。** YOLO（或同类）类名只表示「目标在哪」：`indicator_light` / `panel` / `inspection_region`。巡检结果 `PASS\|FAIL\|UNKNOWN` 由 **ROI/状态规则**（及后续同构判定）给出，**禁止**把检测类名或框类别当验收标签。 |
| 2 | **UNKNOWN 独立覆盖。** 测试集必须含标签为 UNKNOWN 的样本；UNKNOWN 正确 = 预测也是 UNKNOWN。禁止把 UNKNOWN 并进 FAIL 刷分，禁止缺态默认 PASS。 |
| 3 | **按采集批次划分，禁止邻帧随机拆。** 同一 `batch_id`（同一次 Gazebo 会话 / 同 seed 连采 / 同一次连续采图）整批进入 train **或** val **或** test，不得把相邻帧拆进不同 split。**合成/增强帧**须与 `parent_frame_id` 同 split；**正式 test 只用独立原始采集批次**，禁止用增强凑 test。 |
| 4 | **独立测试集在调参前冻结。** `test` 清单与标签一经锁定，禁止用 test 调阈值、改 ROI、早停选模、挑权重；只允许在 train/val（或专用 dev）上迭代。 |
| 5 | **主验收指标 = 端到端状态一致率，不是 mAP。** mAP/框 IoU 可作辅助诊断，**不替换** 5B 门禁。 |

## 2. 检测类（定位层）

| `class_name` | 含义 | 标注 |
|---|---|---|
| `indicator_light` | 单颗指示灯（圆斑） | 每灯一框；一站最多 3 框 |
| `panel` | 面板显示区 | 一站通常 1 框 |
| `inspection_region` | 检查区（含漏液色块所在地面区） | 一站通常 1 框（有/无色块均标区域） |

- 检测标签：**只有类 + 框**，不含 green/red/PASS 等。  
- 漏检：该目标应有框却无框 → 端到端不得默认 PASS（见规格与 I1 接框清单）。

---

## 3. 状态标签（判定层，与检测类分离）

与盘点枚举一致，**勿扩**：

| 对象 | 状态字段 | 允许值 | → 巡检 verdict（规则层） |
|---|---|---|---|
| 灯 | `led`（每槽） | `green` \| `red` \| `yellow` \| `off` \| `UNKNOWN` | 全 green→组件 PASS；任一非绿→FAIL；含 UNKNOWN→保留 UNKNOWN |
| 面板 | `panel` | `lit` \| `dark` \| `UNKNOWN` | lit→PASS；dark→FAIL；UNKNOWN→UNKNOWN |
| 漏液 | `leak` | `none` \| `fixed_fail` \| `UNKNOWN` | none→PASS；fixed_fail→FAIL；UNKNOWN→UNKNOWN |

**站级汇总（报告用）：** 灯/面板/漏液分项 verdict 再 rollup；任一分项 UNKNOWN 则站级不得报「全 PASS」。

**`confidence`：** 仅检测框置信度；**禁止**用其推导 PASS/FAIL/UNKNOWN。

## 4. 样本单元与元数据

- **一张图 = 一个样本单元**（640×480 优先；可含同站多目标）。  
- 每图必须带 sidecar / 表行元数据，字段见 [`M2-5B-采集清单.md`](M2-5B-采集清单.md) §3。  
- 状态 GT 与检测框可同文件分节，但逻辑分层：`detections[]` vs `states` / `verdict_gt`。

## 5. Split：train / val / 独立 test

| Split | 用途 | 约束 |
|---|---|---|
| **train** | 训检测器；可调 ROI 阈值的开发集来源之一 | 可多批次 |
| **val** | 早停、选模、调参、阈值搜索 | 与 train **批次互斥**；**禁止**用 test |
| **test** | **唯一** 5B 门禁报告集 | **调参前冻结**；整批锁定；报告后不得「微调再测同一 test」冒充首次 |

### 5.1 批次划分操作定义

1. 每次采集赋予 `batch_id`（建议：`YYYYMMDD_HHMM_seed{N}_session{k}`）。  
2. 划分时以 `batch_id` 为原子单位抽到某一 split。  
3. **禁止：** 同一批次内按帧号随机 8:1:1；禁止把连续 teleop/瞬移连拍拆进 train+test。  
4. 建议比例（按**批次数**或**图数**声明一种并写进清单）：约 train 70% / val 15% / test 15%；test 须覆盖 §6 分层。

### 5.2 冻结流程

```text
1) 采够清单最低量（见采集清单）并完成标注
2) 公布 test 的 batch_id 列表 + 校验和（或 manifest）→ 冻结
3) 仅在 train/val 上训练与调参
4) 一次性在冻结 test 上出端到端状态一致率报告
```

## 6. 最低样本量建议（首切片，仿真）

> 建议值用于开工，**不是** 90% 承诺。未达下表不得宣称「5B 数据集就绪」。

| 维度 | 最低建议 | 备注 |
|---|---|---|
| 总图数 | ≥ **300** | 含 train+val+test |
| 独立 test 图数 | ≥ **60** | 且 ≥ 3 个互斥 `batch_id` |
| 每检测类（有框实例） | ≥ **150** 实例 | 三站合计；灯类按「颗」计 |
| 灯态 `green` | ≥ 40 图含该态 | |
| 灯态 `red` / `yellow` / `off` | 各 ≥ **20** 图 | `off` 须相机可分（C-off 已修） |
| 面板 `lit` / `dark` | 各 ≥ **30** 图 | |
| 漏液 `fixed_fail` / `none` | 各 ≥ **30** 图 | FAIL 仅柜 B 合法 |
| **UNKNOWN 专用** | ≥ **30** 图 | 见 §7；test 中 ≥ **10** |
| 难例（过曝/遮挡/模糊等） | ≥ **40** 图 | 见采集清单；test 中 ≥ **10** |

距离：优先 **1.2 m 正对**；test 中建议含少量 1.0 m / 1.5 m（各 ≥ 5 图）并在报告中声明构成。

## 7. UNKNOWN 策略

| 项 | 约定 |
|---|---|
| 标签来源 | 人为/合成约定（如 ROI 中间带、模糊不可判、严重遮挡）；与 R1 `U_panel` / `U_leak` 同类 |
| 覆盖 | train/val/test **均**要有；test **强制**有独立 UNKNOWN 子集 |
| 计分 | 仅当 GT=`UNKNOWN` 且预测=`UNKNOWN` 计正确；预测成 PASS/FAIL 均错 |
| 禁止 | 把难例全标 FAIL；把 UNKNOWN 从分母剔除后再报「准确率」 |

## 8. 端到端状态一致率（5B 主口径）

对齐场景规格 §5.1，操作化如下。

### 8.1 定义

对冻结 **test** 集中、属首切片、带状态标准答案的每个**样本单元**（默认：一图 × 一对象字段；报告须声明是「按对象」还是「按站 rollup」——**推荐主报按对象，附站级**）：

\[
\text{状态一致率} = \frac{\#\{\text{预测状态}=\text{GT 状态}\}}{\#\{\text{分母单元}\}}
\]

**分母规则（钉死）：**

| 情形 | 是否进分母 | 是否计「对」 |
|---|---|---|
| GT 有有效状态（含 PASS/FAIL/绿红黄 off/lit/dark/none/fixed_fail）且预测同态 | 是 | 是 |
| GT=UNKNOWN，预测=UNKNOWN | 是 | **是**（唯一算对方式） |
| GT=UNKNOWN，预测=PASS/FAIL/其它态 | 是 | 否 |
| **漏检**（应有对象无框 / 无 Decision） | **是** | **否**（不得默认 PASS） |
| **非法输出**（非法框、退化 ROI、状态词当检测类、协议外字段） | **是** | **否** |
| 把 UNKNOWN 从分母剔除再报「准确率」 | **禁止** | — |

- 灯：按槽位或按「站级灯向量」二选一，**报告必须写清**；推荐 **按槽位**。  
- **主门禁 test 帧**：须为冻结批内、**1.2 m**、`review_passed` 的**原始**帧；aug / `boxes_untrusted` 不得充主门禁分母（可另附辅助切片并声明）。  
- `review_passed` / `test` / `train` 三者不得混用；**84 ≠ 最终 train 规模**。

### 8.2 与 mAP 关系

| 指标 | 角色 |
|---|---|
| 端到端状态一致率 | **门禁**（对应规格 ≥90% 的计算对象；本刀不宣称已达） |
| 异常召回 / 误报 / 逐类状态准确率 | 辅助解释 |
| 检测 mAP / 召回 | 辅助；框好但状态错仍算状态失败 |

### 8.3 报告最低内容

- test `batch_id` 列表与冻结日期  
- 样本构成（距离、站、态、UNKNOWN、难例计数）  
- 按对象一致率 + 可选站级  
- 声明：未用 test 调参

### 11.4 状态 GT 与 UNKNOWN（含主架构师裁决）

- 状态 GT：**场景证据 + 人工审核**；**禁止**模型预测写 GT。  
- UNKNOWN 依据**独立于**待验 ROI 数值阈值；**禁止**为刷分标成模型当前输出。  
- **leak UNKNOWN 允许**进入首切片分母（见场景规格 v0.1.2）；标注依据仍须独立于待验阈值。  
- 漏检 / 处理失败 / 非法输出：按 §8 **进分母且计错**；模型「安全输出 UNKNOWN」**不得**因此自动得分。  
- **遮挡 UNKNOWN 合同（采集前钉死）：** 被遮挡对象若仍要求检测框则框标可见残部 + `states=UNKNOWN`；若约定整目标不可见则该对象槽记漏检（计错）而非用 UNKNOWN 刷分。合同写入该批 `label_version` 备注。  
- 原始 Test **禁止**后处理增强凑数。  
- 临时插入遮挡物、改曝光/材质等属**运行场景改变**；「未改 world 文件」**不等于**已获授权。本专节只提方案，**不实施**场景改动。若无授权手段无法产够 UNKNOWN/难例 → **报告冲突**；**不允许**自动降低 UNKNOWN/难例配额。

### 11.8 冻结顺序（必须）

