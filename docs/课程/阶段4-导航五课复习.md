## 0. 全局图：四个模块各补哪块短板

机器人是一个"又盲又失忆的司机"，阶段 4 就是给它配齐四样东西：

| 模块 | 比喻 | 回答的问题 | 产出 | 阶段 |
|---|---|---|---|---|
| 里程计 odom | 体感 | 我走了多少步、转了多少度 | `/odom` + odom→base_footprint TF | 3.3 |
| SLAM | 画地图 | 环境长什么样 | `maps/test_room`（冻结） | 4.3 |
| AMCL | 看路牌对地图 | 我在地图上的哪 | `map→odom` TF + `/amcl_pose` | 4.4 |
| Nav2 | 导航 App | 怎么过去、卡住怎么办 | `/cmd_vel` | 4.5 |

**信任分层原则（全篇最重要的一句话）：** 短时信体感（odom），长期信路牌
（AMCL），决策信地图（costmap）。4.5b 事故的本质就是一次信任错配。

一条 cmd_vel 的诞生顺序（读参数文件的顺序）：

```text
两张 costmap → 大路线(planner) → 眼前怎么开(controller/DWB)
→ 最后一道闸(velocity_smoother) → 卡住了自救(behavior) → 总指挥(bt_navigator)
```

## 第 1 课：读懂 `nav2_test_room.yaml`

**心法：这个文件不是配置清单，是一份"员工手册"——每个段落是一个岗位
说明书，参数之间互相咬合。**

### 1.1 两张 costmap：为什么是两张

```yaml
local_costmap:  global_frame: odom,  rolling_window: true,  width: 3, height: 3
global_costmap: global_frame: map,   resolution: 0.05,  track_unknown_space: true
```

- **local 用 odom 系**：局部避障管"眼前 3 秒"，用体感坐标就够、且稳——
  不依赖 map→odom 那条可能正在抖的边。
- **global 用 map 系**：全局规划必须落在地图坐标上，否则静态层（来自地图
  文件）和机器人位置（来自体感）根本对不齐。
- `rolling_window: true, 3×3 m`：局部图是绑在车上的"手电筒光圈"，
  ClearCostmap 擦的就是它。
- `update_frequency`：local 5 Hz（动态避障要快），global 1 Hz（大格局变化
  慢，省算力）。
- `track_unknown_space: true`：没扫到过的地方标"未知"而不是当可通行，
  配合 planner 的 `allow_unknown` 构成一对张力。

### 1.2 obstacle layer：costmap 是一块每秒擦写 5 次的白板

```yaml
marking: true / clearing: true
obstacle_min_range / raytrace_min_range: 0.30   # 对齐 robot_v0 激光物理量程
obstacle_max_range: 2.5 / raytrace_max_range: 3.0
```

- `marking`：激光打到 → 画上障碍。`clearing`：激光**穿过** → 擦掉障碍。
  动态避障全靠这对开关：箱子推来 mark 上，搬走 clear 掉。
- `min_range: 0.30` 对齐激光物理最小量程——不改插件的前提下让数据与
  传感器一致（AMCL yaml 里同款参数，两处都要对齐）。

### 1.3 footprint 与 inflation：门宽账

```yaml
footprint: "[[0.20,0.15],[0.20,-0.15],[-0.20,-0.15],[-0.20,0.15]]"
inflation_radius: 0.35  cost_scaling_factor: 5.0
```

- footprint 四角点描出真实车形 0.4×0.3。**与 `robot_radius` 互斥**：两个都写
  Nav2 静默取其一（排障大坑）。用多边形不用圆：圆要按外接 0.25 m 算，
  门里白丢 10 cm 可走空间。
- `inflation_radius`：障碍周围"危险晕圈"最大半径。**晕圈不是禁区**，
  是递减的代价场。
- `cost_scaling_factor`：晕圈衰减速度。5.0 衰减快，给窄通道留活路。
- **门宽账（自己动手算一遍）**：门 1.1 m，栅格 0.05 吃掉边缘 → 自由区约
  1.0 m；footprint 两侧各 0.15 m 为致命区 → **车中心可走带 ≈ 0.7 m**。
  inflation 0.35 < 门中心到墙的 0.55 m，门中心代价为 0——这就是当初敢
  冻结 0.35 的底气：它影响"过门舒不舒服"，不影响"能不能过"。

### 1.4 planner_server：大路线

```yaml
GridBased:
  plugin: nav2_navfn_planner/NavfnPlanner
  tolerance: 0.5
  allow_unknown: true
```

NavFn = Dijkstra 快速版：在全局图代价场上"泛洪"，梯度下降到目标。
- `allow_unknown: true`：允许穿未知区，避免过度保守。
- `tolerance: 0.5`：**暗雷**——目标不可达时允许把终点落在 0.5 m 内的次优
  位置。goal checker 不认次优点，车会在目标前徘徊到被判"没进展"。
  排障清单里给它留一行。

### 1.5 controller_server：DWB——"每秒猜 20 次"

```yaml
controller_frequency: 20.0
progress_checker:  required_movement_radius: 0.25   # 4.5b 第一刀（原 0.5）
general_goal_checker:  xy_goal_tolerance: 0.10      # 3.0 收紧（原 0.15）
```

**`xy_goal_tolerance` 出现两次（goal_checker 一处 + FollowPath 一处），
不是重复**：前者是考官（判到没到），后者是司机的预判（DWB 靠它决定何时
切入 RotateToGoal 原地转向）。**两处必须一致**——只改考官，司机会在
0.15 m 就原地转，永远进不了 0.10 的圈。

```yaml
max_vel_x: 0.15          # 4.4 教训：AMCL 动态误差的预算
sim_time: 1.7            # 每条候选轨迹向前模拟 1.7 s
vx_samples: 20  vtheta_samples: 20   # 速度×转速 20×20 档 ≈ 400 种候选
```

- `sim_time` 与局部图咬合：0.15 m/s × 1.7 s = 0.26 m，只占 3 m 光圈一角，
  安全。改一个要想想它的啮合件。
- 限速 0.15 是**保守选择不是天花板**：前提是 alpha 配错（见第 2 课）。
  修后可试 0.25~0.3；真要提速上 EKF（手册阶段 4 可选项）。

critics = 打分规则的"嗓门"：

```yaml
critics: [RotateToGoal, Oscillation, BaseObstacle, GoalAlign, PathAlign, PathDist, GoalDist]
PathDist.scale: 32.0   GoalDist.scale: 24.0   BaseObstacle.scale: 0.02
```

PathDist 嗓门最大（最怕偏离全局路线）；BaseObstacle 只有 0.02——**硬
约束不靠它**：致命格里的候选直接判死，BaseObstacle 只管"贴墙 vs 走中间"
这种软偏好。硬的要命，软的才谈价。

### 1.6 velocity_smoother：出厂前的最后一道闸

```yaml
max_velocity: [0.20, 0.0, 1.0]   feedback: OPEN_LOOP
```

磨平 DWB 的指令抖动（限幅、限加减速度）。**上限 0.20 > DWB 0.15 是对的**：
它是天花板不是目标值，天花板必须高于巡航速度，否则变成偷偷限速。

### 1.7 behavior_server + bt_navigator：自救与总指挥

```yaml
behavior_plugins: [spin, backup, drive_on_heading, assisted_teleop, wait]
global_frame: odom    # 自救在 odom 系跑
```

自救动作是"眼前的局部动作"，用体感坐标——**不依赖可能正在出错的
map→odom 边**，设计本意是隔离。但 Spin 在重复结构走廊上自带毒性
（第 2 课）。BT 默认剧本 = 算路→跟路，外面包一层"失败→清图→Spin/BackUp"
轮询恢复；4.5b 准备的"去 Spin/BackUp BT 副本"就是改剧本，但没用上。

3. inflation_radius 0.35 → 0.55，门里"车中心可走带"变多少？影响"能不能过"

## 第 2 课：AMCL 粒子滤波与 alpha 事故完整复盘

**教材：`amcl_test_room.yaml` + `bags/patrol_diag` 录证数据**

### 2.1 粒子滤波四步循环

AMCL 肚子里是几百上千个"猜测点"（粒子），每个说"我觉得我在这"：

```text
initialpose：给所有粒子一个起跑位置（充电垫附近）
   ↓ 每次更新：
① 预测：按里程计把所有粒子搬到新位置（顺带撒 alpha 噪声）
② 观测：来一帧激光 → 每个粒子打分
   （"如果我在这，激光该扫到什么形状" vs 实际形状 → likelihood field 比对）
③ 重采样：得分高的繁殖、得分低的淘汰
④ 输出：幸存粒子的重心 = 新图钉位置（map→odom TF）
   ↓ 循环，永不停止
```

**图钉是海选出来的冠军，不是钦定的。** initialpose 只决定起跑位置。
它没有"冠军不许站在墙里"的规则——投票被带偏时，图钉可以落进墙格子。

### 2.2 参数地图（每个参数在循环里的角色）

```yaml
min_particles: 800  max_particles: 3000   # ③ 参选人数：多=稳但费算力
resample_interval: 1                      # ③ 每轮都重采样
pf_err: 0.05  pf_z: 0.99                  # ③ 重采样精度要求
alpha1–5: 0.05                            # ① 运动噪声（原 0.2，4.5b 改）
update_min_d: 0.05  update_min_a: 0.10    # 触发阈值：动 5cm / 转 0.1rad 才更新
laser_model_type: likelihood_field        # ② 打分模型
max_beams: 60                             # ② 每帧抽 60 束参与比对
laser_max_range: 8.0  min_range: 0.30     # ② 与 robot_v0 物理量程对齐
z_hit: 0.5  z_rand: 0.5  sigma_hit: 0.2   # ② "命中真墙"与"乱碰噪声"的混合比
transform_tolerance: 0.5                  # TF 时效容忍
```

- **alpha 的读法**："我多不相信自己的里程计"。alpha 大 = 每步把粒子撒一大片
  让激光全图重找自己；alpha 小 = 相信里程计，粒子抱团跟 odom 走，激光只做
  "原地确认"。
- `update_min_d/a`：太密费 CPU，太疏则转弯/慢速时更新滞后。0.05/0.10 对
  0.15 m/s 的车 = 每秒必更新。
- `z_hit/z_rand`：真实场景激光既命中墙也命中噪声，0.5/0.5 是常见起点。

### 2.3 为什么图钉会跳：alpha 事故完整复盘

**证据一（T3，阶段 4.2b）**：仿真 odom 尺度因子 1.0000，22.47 m 路径误差
< 1 mm，航向误差 0.0°——**里程计近乎完美**。

**证据二（4.4）**：alpha=0.2 时静止定位 max 0.062 m——静态没问题，因为
静止时粒子有充足时间收敛。

**事故链（4.5b，patrol_diag 录证）**：

```text
① alpha=0.2 高估噪声几个数量级 → 每条腿粒子被撒开一大片
② 出 A 门（首次自救前）AMCL 已偏 0.59 m —— 门口是模糊期
③ progress_checker（0.5m/10s）对 0.15 m/s 慢车在门口误触发
④ BT 自救升级到 Spin —— 原地旋转时激光画面拖影，真位置得分被拉低
⑤ 撒开的粒子群在"准周期走廊"（每 2~4 m 一个同款门洞）里挑了错峰
   → 首 Spin 时 |AMCL−GT|≈1.5 m，particle rms≈2.4 m
⑥ 错误位姿后来落进静态地图 OCCUPIED → NavFn 起点在障碍里
   → compute_path 反复 ABORT
⑦ ClearCostmap 救不了：它只擦动态层，静态层来自地图文件擦不掉
   → 死循环 → ABORT
```

**两段式机理要记住**：alpha 撒开是第一段（根因），Spin 拖影是第二段
（放大器）。所以修复阶梯里**第 2 刀（alpha）单独生效**，2.3/2.4 不需要启用。

**修复与回归**：

| 步 | 改动 | 回归结果 |
|---|---|---|
| 2.1 | `required_movement_radius` 0.5→0.25 | 走廊 PASS，无 Spin/BackUp |
| 2.2 | alpha1–5 0.2→0.05（受控解冻，依据 T3） | 4.4 静止 max=0.074 m ≤0.10 |
| 2.3/2.4 | 去 Spin BT / 站点重锚定 | **未启用**（1+2 已够） |

**alpha 改后静止误差 0.029→0.074 m，变"差"了但这是预期**：alpha 大时
估计是一大片粒子的平均值（迟钝但稳），alpha 小后估计更"跟脚"（灵敏），
静止时在真值附近小幅抖动。动态跟得紧才是导航要的，0.074 就是新基线。

**提速路线**：alpha 修好后可试 0.25~0.3 m/s；真机要快（1~2 m/s）上
`robot_localization` EKF 融合 odom+IMU——EKF 不看激光不看地图，它把
"两帧激光之间车在哪"的预测做扎实，AMCL 专心对指纹。

## 第 3 课：`navigate_to_pose_gate.py` 走读——Action Client 模式

**教材：`scripts/navigate_to_pose_gate.py` + `scripts/coords.py`**

### 3.1 为什么用 Action 不用 Topic/Service

| 通信 | 适合 | 为什么这里不行 |
|---|---|---|
| Topic | 持续数据流 | 没有"完成"概念，没有反馈 |
| Service | 一问一答即时返回 | 导航要跑几十秒，不能阻塞等 |
| **Action** | **长任务 + 进度反馈 + 可取消** | ✅ NavigateToPose 就是 Action |

### 3.2 异步回调链（骨架）

```python
send_goal_async(goal, feedback_callback)      # 发出
  → _on_goal_response                          # accepted?
      → get_result_async()
          → _on_result                          # SUCCEEDED？
              → _capture_goal_errors()          # 抓到点瞬间的误差
              → stopped_sampling = True         # 开 1s 采样窗（门控开关）
              → create_timer(1.0, _finish_stopped_check)
                  → _analyze_stopped_window() → _print_report()
```

三个设计要点：

1. **全程事件驱动，没有一个 sleep 轮询**。采样窗靠 `_on_odom` 里的
   `if not self.stopped_sampling: return` 门控——result 回调置位后才开始
   收样本，1 s 定时器到点收窗分析。这保证"停稳 1 s"量的是真窗口。
2. **主循环是 `while not node.done: spin_once(0.1)`** 而不是 `rclpy.spin`：
   保留对退出时机和 exit code 的控制（`FINAL: PASS` ↔ exit 0，可接 CI）。
3. **use_sim_time 必须显式注入**，且先等 `/clock` 非零再建 timer——否则
   时间戳全卡 0（仿真环境的经典坑）。

### 3.3 坐标系纪律：只转一次

```python
mx, my = world_to_map_xy(world_x, world_y, ox, oy)   # 构造 goal 时转一次
...
self.pos_err = math.hypot(gt_x - self.world_x, ...)  # 误差全在 world 系算
```

ground_truth 是 world 系，A/B/C 冻结坐标也是 world 系——直接相减。
AMCL diag 列例外：`amcl_pose` 是 map 系，所以要比的话 GT 也减 origin。
**同一脚本里坐标系只 crossing 一次，出错面最小。** 转换函数统一来自
`scripts/coords.py`（禁止第三次手算）。

### 3.4 QoS：两类订阅两种配置

```python
/ground_truth /odom  → qos_profile_sensor_data（BEST_EFFORT）
/amcl_pose           → RELIABLE + TRANSIENT_LOCAL
```

- 传感器流：容忍丢帧、要低延迟 → BEST_EFFORT。
- `amcl_pose` 低频（~0.5 Hz）且想拿到"最近一条" → RELIABLE；
  `TRANSIENT_LOCAL` 让**晚加入的订阅者也能收到最后一条**——AMCL 车不动时
  30 s 只发一条 pose，靠它才拿得到。

### 3.5 停稳判定：沉降语义（3.0c 的教训）

```python
PASS = settle ≤ 1.0 s 且沉降后无再次超标
settle = 窗口内第一个 |v|<0.02 且 |ω|<0.05 的时刻
```

规格 §5 原文是"到位后 1.0 s 内 |v|<0.02"——**沉降时间预算**，不是
"窗口内每个样本都达标"。旧实现收严了一层，把 100 ms 的刹车短尾判成 FAIL
（3.0b：max|v|=0.054，100 ms 进阈值，之后 900 ms 干净）。**先读冻结规格
原文，再写判定代码**——考官比规格严也是错。

**diag 列的用途**：`AMCL vs GT` 把总误差拆成"定位误差"+"控制器误差"。
位置差但 diag 小 → 调 DWB；diag > 0.1 → 查定位。**先归因再动手。**

## 第 4 课：`patrol_mission_node.py` 走读——状态机与链式任务

**教材：`ros2_ws/src/inspection_mission/inspection_mission/patrol_mission_node.py`**

### 4.1 结构：一张小状态机

```text
kickoff(0.5s 定时器，只发一次)
  → _prepare_and_send：清两张 costmap → 发当前航点 goal
      → SUCCEEDED → dwell 2s 定时器 → _prepare_and_send（下一航点）
      → 失败     → attempt<2 ? 清图重发 : FAIL 退出
  → 航点耗尽 → FINAL PASS（exit 0）
```

每个设计决定都有理由：

- **dwell 2 s**：让 AMCL 在新位置稳定、costmap 反映当前位姿、刹车完全沉降，
  再发下一个 goal——不给链上的上一段留尾气。
- **同点重试 1 次且先清 costmap**：上次失败残留的 mark 障碍可能已消失
  （动态层），清掉给重规划干净视野。注意静态层清不掉（第 2 课⑦）。
- **顺序 A→C→B 的取舍**：先按与 3.1 单点一致的路径验证，规格顺序 A→B→C
  后补测通过（C 重试 1 次，recoveries=2）。**改顺序要记录，不能悄悄改。**
- **goal 构造**：用 `coords.py` 的 world→map 转换 + `yaw_to_quat`，
  frame_id=map——与 gate 脚本同一套转换，不重复造轮子。
- **`spin_once` 主循环 + `_done` 标志 + exit code**：与 gate 脚本同款骨架。
- **超时 timer**：`GOAL_TIMEOUT_SEC=300`，超时先 `cancel_goal_async()` 再
  FAIL——优雅取消比硬杀干净（Nav2 会执行取消流程停车）。

### 4.2 为什么不用 waypoint_follower / follow_waypoints

Nav2 自带 `FollowWaypoints` action 能一次收整条航点列表。自写循环的优点：
**每一段的成败、重试、dwell 完全可控、可日志、可扩展**（阶段 6 要在到点后
插"拍照+检测"钩子——状态机里加一行就行）。这是"任务层"的雏形，
也是 `inspection_mission` 包存在的意义。

## 第 5 课：方法论复盘——一次"玄学故障"的标准解剖

**教材：4.5b 全过程（本课没有代码，只有决策链）**

### 5.1 事件时间线

```text
冒烟通过(走廊 0.170m) → 3.0 收紧 xy_tol 0.15→0.10（预算分析驱动）
→ 3.0b Stopped FAIL（n=1 不定性，先加诊断）→ 3.0c 沉降语义对齐规格
→ 3.1 A/C/B 单点全绿（×2）→ 4.5b patrol 连续跑挂（第 2 航点 ABORT）
→ 停止空转 → 带仪器复现（bag + 3 节点日志）→ 因果链坐实
→ 阶梯修复（2.1 → 2.2，每步回归）→ A→C→B 与 A→B→C 双 FINAL PASS
```

### 5.2 五条工程教训（比 ROS 知识更值钱）

1. **闸门驱动开发**：先定量化及格线（0.10/0.20/10°），数字达标就停。
   每次改参都有数据依据（0.170 离 0.20 只剩 3 cm → 收紧到 0.10）。
2. **一次只改一个变量**：alpha 和 progress_checker 分两步走、每步回归，
   所以能明确归因"哪一刀治了病"。
3. **验收必须测到它声称的能力**：3.1 的"×2 PASS"第二遍是原地转向，
   冒充了重复性测试——链式脆弱性直到 4.5b 才被执行到。
   **重复性测试必须让机器人真的重新执行任务**（换起点/重跑全程）。
4. **先仪器化复现，再动手修**：bag + 日志把"Spin 时刻 = 粒子 rms 暴涨时刻"
   钉死后，每刀都打在证实的病灶上。n=1 不定性为 flake。
5. **冻结与受控解冻**：AMCL 文件写"勿改"，动它时走程序——
   拿出 T3 证据 → 说明理由 → 改后回归验收（0.074 ≤ 0.10 过）。

### 5.3 排障通用流程（背下来）

```text
现象（ABORT / 漂移 / 不动）
→ 分层归因：地图？定位？规划？控制？执行？（diag 列就是为此而生）
→ 只看最相关一层，只改一个参数
→ 回归测试（上游闸门 + 当前场景）
→ 记录：改动、依据、回归数据
```

### 第 5 课自测（口述题，无标准答案，对照 5.2 检查要点是否覆盖）

1. 用 3 分钟向面试官讲清 4.5b 故障的因果链和你的修法。
2. 如果 2.1+2.2 之后 patrol 仍然挂，你的下一步是什么（提示：阶梯还剩什么，
   以及为什么站点重锚定是兜底不是首选）？

## 附录 B：参考答案

**第 1 课**

1. local 用 map：AMCL 一跳，局部避障眼里的"车在哪"跟着跳，车会瞬移/
   误判障碍位置甚至原地抽搐；global 用 odom：静态层（map 系）和机器人
   位置（odom 系）对不齐，长路线没法算。信任分层被打乱，两头都坏。
2. 司机在 0.15 m 就切 RotateToGoal 原地转，转完自认为到位停车——停在
   0.15 m 处，永远进不了考官的 0.10 圈 → follow_path 永不满足 → 反复
   微调直到 progress 判定/超时。两处参数必须成对改。
3. 可走带由 footprint 致命区决定（≈0.7 m），inflation 只涂代价场：
   0.55 时门中心代价从 0 变成约 43（低但不为零），**仍能过**，但 DWB
   更贴中线、贴边代价变高。影响"舒不舒服"；只有当晕圈把整条通路涂成
   高代价且无替代路时才会间接影响规划选择。

**第 2 课**

1. alpha 大时定位估计是一大片粒子的平均值（迟钝但平滑）；alpha 小后
   粒子抱团、估计灵敏，静止时在真值附近小幅抖动。导航要的是动态跟得紧，
   0.074 仍在闸门内，是合理代价与新基线。
2. 车动 0.5 m / 转 0.5 rad 才更新一次：0.15 m/s 时 3.3 s 才更新一次，
   门口/转弯的快速变化完全漏采，激光修正频率不足，误差只涨不修。
3. 因为它们被同一个错误观测"锁"住了：粒子本身有先验相关性（都是同一
   群体的后代），在重复结构里错位置的真实得分不低于正确位置，重采样
   会让高分错误簇垄断下一代——个体乱飘是噪声，集体跳变是结构。

**第 3 课**

1. odom/GT 是高频传感器流：偶发丢帧无妨、要低延迟 → BEST_EFFORT；
   amcl_pose 低频且"最新一条"就是全部信息，RELIABLE 保必达，
   TRANSIENT_LOCAL 让后启动的验收脚本也能立刻拿到最近一条。
2. 防止采样窗外的 /odom 混进停稳样本——只有 result 回调置位
   `stopped_sampling` 后才收样本，保证 1 s 窗口干净、事件驱动而非轮询。
3. GT 和目标都在 world 系，直接减即可；amcl_pose 在 map 系，要和 GT 比
   必须同系（GT 减 origin）。**比较前先确认两个数在同一个坐标系。**

**第 4 课**

1. 防"带着上一段的尾气发车"：AMCL 未稳、costmap 未反映新位姿、刹车未
   沉降时发新 goal，容易首段就规划失败或定位抖动。删掉可能复现 4.5b
   类型的连锁失败。
2. `rclpy.spin` 阻塞直到 Ctrl-C，退出码和退出时机不受控；`spin_once`
   循环让节点能在 `_done` 时优雅退出并返回 PASS/FAIL 对应的 exit code。
3. 清掉的是动态层 mark 的障碍（上次失败时激光画上的、可能已消失）；
   清不掉的是静态层（来自地图文件）——所以"图钉在墙里"的死局清图救不了。

**第 5 课**

口述题。第 1 题要点：闸门数据→假象（×2 第二遍是原地）→ 链式暴露 →
仪器化复现（bag 日志钉死 Spin 与粒子暴涨重合、AMCL 进 OCCUPIED）→
两段式机理（alpha 撒开为根因、Spin 为放大器）→ 阶梯修复单变量+回归 →
双顺序 FINAL PASS。第 2 题要点：还剩 2.3（去 Spin/BackUp BT）与
2.4（站点重锚定）；重锚定是兜底因为它只在"到站后"生效、治标不治本，
且真实 AMR 中属于标准设计而非作弊——但先用尽根因手段再用它。
