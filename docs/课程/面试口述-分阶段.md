## 阶段 2 · ROS2 通信地基

### 60 秒版（背这个）

> ROS2 通信我只记一个判据：**任务要多久、要不要途中对话**。持续数据流用 **Topic**（激光、图像、里程计）；瞬时一问一答用 **Service**（查机器人状态）；要跑几十秒、要进度、要能取消的长任务用 **Action**（goal / feedback / result），我们 Nav2 的 `NavigateToPose` 和未来的 `PatrolTask` 都是 Action，不是 Service。
>
> 节点是 `init → Node → spin → shutdown` 的事件循环，**回调里不能塞重活**——阶段 5 YOLO 推理不能堵在图像回调里。参数是 **declare → yaml → launch** 三段式，yaml 顶层键必须等于节点 `name`，否则静默不生效。
>
> 自定义接口在 `inspection_interfaces` 里先定契约：`Detection` 给 YOLO 节点发检测结果，`AnomalyEvent` 给异常管理器，`RobotStatus.srv` 给 Web/查询，`PatrolTask.action` 给阶段 6 巡检任务外壳。Action 结束必须 `succeed/canceled/abort` 盖章，不能光靠 return。
>
> TF 是一棵坐标树，**每条边只有一个发布者**；静态边用 StaticBroadcaster（迟到订阅者也能拿到），动态边用 TransformBroadcaster。demo 里的假 TF 真车上要换成 URDF + robot_state_publisher。

### 关键词条

| 被问到 | 答一句 |
|---|---|
| Topic vs Service vs Action | 时长 + 方向；广播 / 打电话 / 点外卖 |
| ROS1 vs ROS2 | ROS1 有 Master；ROS2 DDS 自动发现，但要配 QoS |
| 回调铁律 | spin 单线程，回调堵了全系统卡 |
| `---` 在接口文件里 | srv 一刀两段，action 两刀三段 |
| yaml 参数不生效 | 先看 declare，再看节点名是否对上 yaml 顶层键 |
| 两个节点发同一条 TF | 会跳变；URDF 应是单一事实源 |

## 阶段 3 · 机器人模型与 Gazebo

### 60 秒版（四课合一）

> 阶段 3 两个 xacro：**URDF 管形状质量关节，Gazebo 扩展管摩擦、驱动、传感器**。导航原点钉 **base_footprint**（地面投影），不是 base_link 中心。link 三块 visual/collision/inertial 缺一不可。
>
> diff_drive 收 `/cmd_vel_gazebo` 动车、读轮子造 `/odom`；`wheel_separation`/`wheel_diameter` 填错里程计系统性偏。`/cmd_vel` 经 **cmd_vel_timeout** 超时刹车，插件层与安全层分开。p3d 导出 `/ground_truth` 是**仿真尺子**，真机没有。
>
> 激光 ray 插件发 `/scan`：自车红点三因三治——laser_link 无 collision、光心抬高、**min_range 0.30** 大于车身半径；min_range 由车尺寸决定不是想看多近。
>
> 相机 Classic 光轴沿 **+X**，按 −Z 教程乱补 pitch 越调越朝地；修法是前杠低位 + sensor pose 恒等 + joint 不写 rpy。**camera_optical_frame** 是机械系到光学系的桥，阶段 5/6 像素投影用。

### 关键词条

| 被问到 | 答一句 |
|---|---|
| base_footprint | 地上导航原点；与车身尺寸解耦 |
| diff_drive | 收速度驱轮；读轮造 odom |
| cmd_vel vs cmd_vel_gazebo | 上层接口 vs 插件执行；中间 timeout 刹车 |
| p3d / ground_truth | 仿真标准答案；真机无上帝视角 |
| 自车红点 | 无 collision / 抬高光心 / min_range≥车半径 |
| Classic 相机光轴 | +X 朝前；optical_frame 是 Z 前（视觉层） |
| scale（T3） | odom 路程 ÷ 真值路程；1.0 = 机械参数填对 |

## 阶段 4 · 导航主链

### 60 秒版（第 0–2 课）

> 阶段 4 给「又盲又失忆的司机」配四样：**odom 体感、SLAM 地图、AMCL 定位、Nav2 走到点**。信任分层：**短时信 odom，长期信 AMCL，决策信 costmap**。
>
> **算路员 NavFn**：在 global 代价栅格上从终点泛洪算每格最小代价，再从起点沿代价下坡出路径——经典图搜索，不是 AI。local 用 odom 防抖，global 用 map 对齐墙图。
>
> **AMCL（地图定位）**：几百个粒子猜位置；每轮 **预测（odom+alpha 噪声）→ 激光打分（likelihood_field）→ 重采样 → 输出 map→odom**。图钉是海选冠军，不是 initialpose 钦定；冠军可以落进墙里。**alpha=多不信 odom**；T3 证明 odom 近乎完美，alpha 0.2 撒太大是 4.5b 根因，改 0.05。静止误差 0.029→0.074 m 是变灵敏的预期，不是坏了。
>
> **4.5b 事故链（两段式）**：根因 alpha 撒开 + 放大器 Spin 拖影 → progress_checker 误触发 → Spin → 准周期走廊错峰跳变（|AMCL−GT|≈1.5 m）→ 位姿进静态墙 → NavFn 起点在障碍里 ABORT，ClearCostmap 救不了。修：progress 0.5→0.25 + alpha 0.2→0.05，阶梯单变量回归。patrol 才是真链式验收。

### 关键词条（第 1–2 课）

| 被问到 | 答一句 |
|---|---|
| local vs global costmap | local=odom 眼前 3m；global=map 大路线 |
| NavFn / 算路员 | 栅格泛洪+Dijkstra 思想，输出 global 路径 |
| marking / clearing | 激光打到画障碍；穿过擦掉 |
| AMCL 四步 | 预测→观测→重采样→输出 map→odom |
| alpha | 运动噪声；大=不信 odom 撒开；小=跟 odom 激光微调 |
| initialpose | 粒子起跑位置，不是终身钦定 |
| particle_cloud | 粒子不确定性；散得大=定位不信 |
| likelihood_field | 激光打分：粒子位姿下 scan 与地图像不像 |
| update_min_d/a | 动够 5cm/转够 0.1rad 才更新，省 CPU |
| xy_goal_tolerance 两处 | goal_checker 考官 + FollowPath 司机，必须一致 |
| progress_checker | 10s 内没走出半径 → recovery → 4.5b 点火 |
| ClearCostmap 救不了静态墙 | 只擦动态层，进墙位姿要修定位 |
| 4.5b 两段式机理 | 根因 alpha 撒开；放大器 Spin 拖影；2.2 单独生效 |
| 静止 0.074 m | alpha 小=灵敏跟脚；闸门 ≤0.10，是新基线不是退化 |
| T3 与 alpha | scale=1.0、22 m 误差 <1 mm → 该信 odom，不该撒大噪声 |
| /odom vs AMCL | odom=轮积分短期；AMCL=激光对地图长期；p3d 仅仿真尺子 |

### 第 2 课口述补充（30 秒，可接 60 秒版后面）

> AMCL 不替代 odom：odom 每帧给「走了多少」，AMCL 用激光把 odom 系整体钉回 map。输出是 **map→odom** 这条修正边，不是另造一套位姿。粒子云散=不确定，聚束=收敛；门口、Spin 后看 particle_cloud 最直观。改 alpha 要走受控解冻：拿 T3 证据 → 说明理由 → 改后回归 4.4 静止闸门。
