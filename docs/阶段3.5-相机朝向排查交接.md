## 最终方案（现行代码）

### 布局（`base_link` 系）

```text
base_link
  ├── laser_link     x=0.05, z=0.07（3.4 不动）
  └── camera_link    x=0.215, z=0.02  ← 前保险杠低位，光心离地约 0.12m
        └── camera_optical_frame
```

| 参数 | 值 | 含义 |
|---|---|---|
| `camera_offset_x` | 0.215 | 车头前立面 x=0.20 + 半深 0.015 |
| `camera_offset_z` | 0.02 | 相对 `base_link` 中心，低于车顶 |
| sensor `<pose>` | `0 0 0 0 0 0` | **恒等，无需旋转** |
| `camera_joint` rpy | `0 0 0` | 禁止写 rpy |

### 关键认知（血泪教训）

**Gazebo Classic 11 相机光轴沿传感器坐标系 +X，不是 ROS 文档常说的 -Z。**

因此在 `camera_link` 与 `base_link` 同向时：
- ✅ sensor pose 恒等 → 视锥水平朝车头 +X
- ❌ `pitch=+1.5708` → 把 +X 转成 **-Z（朝下）** → `rqt` 俯视蓝顶

此前多轮失败，根因是误用了「光轴 -Z，需 pitch 90°」这套 **Ignition/部分教程** 的约定。

### SDF 验收快照

```bash
xacro ros2_ws/src/robot_description/urdf/robot_v0.urdf.xacro > /tmp/r.urdf
gz sdf -p /tmp/r.urdf > /tmp/r.sdf
grep camera_mount /tmp/r.sdf          # 应为空
grep -A30 "sensor name='camera'" /tmp/r.sdf | grep pose
# 期望：0.215 0 0.12 0 0 0（base_footprint 系，旋转全 0）
```

## 排查历程（经验归档）

### 时间线

| 阶段 | 尝试 | 结果 |
|---|---|---|
| v1 | `camera_joint` 写 `rpy` 朝前 | visual/sensor 分裂，视锥朝天，画面全灰 |
| v2 | joint rpy=0，sensor `pitch=1.5708` on `camera_link` | 冒烟绿，但 GUI 视锥朝下（**根因：+X 光轴被错误旋转**） |
| v3 | 加 `camera_mount_link` 支架 + 多 visual | lump 后杆与黑盒 pose 分裂，外观悬空 |
| v4 | `preserveFixedJoint` 保 link 独立 | 外观仍分裂，朝向仍朝下 |
| v5 | ChatGPT 方案（保支架调几何） | 未采用；GLM 指出 pitch 方向性错误 |
| **v6 终版** | **拆支架，低位 bumper cam，pose 恒等** | **GUI 几乎完美通过** |

### 根因 A：URDF→SDF 固定关节合并

`camera_joint` 写 `rpy` 时，合并后 visual 与 sensor 的 roll/pitch/yaw 不一致。

**仍有效的原则：** joint 只写 `xyz`；旋转（若真需要）写在 sensor `<pose>`，且必须以 `gz sdf -p` + GUI 视锥验证。

### 根因 B：支架 + `preserveFixedJoint` 的外观分裂

- 默认 lump：所有 fixed 子 link 的 visual 合并进 `base_footprint`，pose 与 TF 树脱节 → 杆子在车顶、相机悬空
- `preserveFixedJoint`：link 独立了，但多 visual 仍难在 Gazebo GUI 里对齐
- **结论：** 阶段 3 装饰性支架不值得为此付出复杂度；真机外观用一体 nose mesh 更稳

### 根因 C：错误的光轴假设（最致命）

| 假设 | 实际（Gazebo Classic 11） | 后果 |
|---|---|---|
| 光轴沿 -Z | 光轴沿 **+X** | `pitch=1.5708` 把相机转向地面 |
| 冒烟 std 检测够 | 俯视蓝顶也能过 | 自动化误报绿，掩盖朝向错误 |

### 根因 D：激光与相机布局冲突

旧方案相机 z=0.13，激光扫描平面 z≈0.12，相机盒被扫描平面穿过 → 仿真/真机都是坏布局。

**终版：** 相机降至 z=0.02（`base_link`），光心离地 0.12m，**低于**扫描平面，前向 FOV 不再被雷达圆柱挡主体。

### 自动化验收的盲区

`smoke_test_stage35.sh` 只校验：话题存在、640×480、`frame_id`、像素 std>阈值。  
**俯视车身（上灰下蓝）同样能过。** 阶段 3.5 必须以 **GUI 视锥 + rqt 前方障碍 + WASD 随动** 为最终闸门。
