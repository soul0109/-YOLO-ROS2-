## 0. 这步在项目里干什么？你要巩固什么？

T3 不是「再遥控玩一圈」，而是在进 SLAM 之前，用**可复现的数据**回答一个问题：

> **轮式里程计（`/odom`）相对真实位姿，漂多少、往哪漂？**

### 0.1 在系统分层里的位置

```text
物理层     Gazebo 仿真引擎 → base_footprint 真实位姿
插件语义层 diff_drive 积分轮速 → /odom（odom 坐标系）
           p3d 直读位姿     → /ground_truth（world 坐标系）
数据层     rosbag2 录下来 → Python 对齐、算误差、出图
导航层     SLAM/AMCL 用激光把「我在哪」拉回 map
规划层     Nav2 按航点走（不再手开）
```

**T3 只验插件语义层 + 数据层**，故意不引入 SLAM/规划误差，所以路线用手开、且不必开得「很标准」。

### 0.2 作品集 / 面试能讲什么

| 你能说的 | 对应证据 |
|---|---|

| 知道何时该调轮径、何时该上 AMCL | scale≠1 → 改 xacro；漂移涨 → AMCL 必开 |

### 0.3 和后面阶段的衔接

| 若 T3 发现… | 下一步 |
|---|---|
| scale ≈ 1，漂移小（本次） | **不改** diff_drive，直接 SLAM |
| scale 偏离 >3% | 先改 `wheel_radius`，再重跑 T3 |
| 漂移随路程明显涨 | SLAM 建图可忍；**AMCL 必须**定期激光修正 |

真机要不要 p3d？**不要**——真机没有 Gazebo 真值；T3 是仿真标定手段，真机靠 GPS/反光板/激光定位。

## 1. 实验目的

在进 SLAM/Nav2 之前，量化 **diff_drive 轮式里程计**相对仿真真值漂多少：

| 话题 | 来源 | 可信原因 |
|---|---|---|
| `/ground_truth` | `libgazebo_ros_p3d.so` 直读 `base_footprint` | 物理引擎位姿，无轮积分 |
| `/odom` | `libgazebo_ros_diff_drive.so` 轮速积分 | 与真机相同链路，会有累积误差 |

**手动走一圈的原因：** 路线与巡检环一致（~20 m、过三门），隔离「规划误差」，只评里程计。

## 4. 方法说明

### 4.1 真值从哪来？

p3d 插件每 20 Hz 读取 Gazebo 中 `base_footprint` 在世界系下的位姿（**不设 frame_name** = 以 world 为参考），发布为 `/ground_truth`（`nav_msgs/Odometry`），噪声设 0。remap 键为插件默认话题 `odom` → `ground_truth`。

### 4.2 为什么要对齐起点？

- `/odom` 的 **odom 系**：出发时刻机器人 = (0,0)
- `/ground_truth` 的 **world 系**：充电垫约在 (0.9, 3.0)

不对齐会看到**大常数平移**，误以为漂移很大。脚本对两路轨迹均：

1. 减去首帧 (x, y)  
2. 旋转使首帧航向对齐到 0  

再比较形状与误差随路程增长。

### 4.3 尺度因子

\[
\text{scale} = \frac{\text{odom 路径总长}}{\text{真值路径总长}}
\]

diff_drive 路程 ∝ `wheel_diameter`。scale > 1 → 轮径设大了；< 1 → 设小了。

## 5. 判读结论（2026-08-31 VM）

**实验记录：** `bags/odom_drift/run_20260831_083749` · 时长 221 s · 真值路程 22.47 m

| 指标 | 结果 | 参考 |
|---|---|---|
| 真值路程 | **22.47 m** | ~18–22 m ✓ |
| odom 路程 | **22.47 m** | 与真值一致 |
| 尺度因子 | **1.0000** | ≈1.00 为佳；偏离 >3% 查轮径 |
| 最大位置误差 | **< 0.001 m** | 仿真差速车常见 0.1–0.5 m / 20 m |
| 最大航向误差 | **0.0°** | 转弯段抬头属正常 |
| p3d spawn 抽检 | (0.905, 3.000) | 与航点 0 一致 ✓ |

**结论：**

> 尺度因子 **1.0000**，全程位置/航向误差在毫米级；**可直接进入 SLAM**，无需调整 `wheel_radius`。仿真理想条件下 diff_drive 与 p3d 几乎重合——**不代表真机也如此**；后续 AMCL 仍必须开启，用激光抑制长期累积。

**对 SLAM/AMCL 的启示：**

- 本环境 odom 基线极好 → SLAM 建图时 scan matching 主导，odom 主要作运动先验  
- 真机或加滑移模型后漂移会变大 → 本曲线作「仿真下界」对比  
- 简历可写：「在 test_room 巡检环上量化轮式里程计，scale=1.0，22 m 路径误差 <1 mm」

## 6. 学习问答

### p3d vs `/odom` 各经过什么？

```text
/ground_truth: Gazebo 物理状态 → p3d 插件 → 话题（无积分）
/odom:         轮关节 → diff_drive 用轮径/轮距积分 → 话题
```

### 轮径与尺度因子？

积分步长 ∝ 轮转角 × 轮径。直径偏大 5% → 路程约偏大 5%（scale ≈ 1.05）。

### 手开路线不标准会影响结论吗？

不会显著影响。脚本对齐首帧位姿，评的是**轨迹形状与累积误差**，不是 Nav2 级到点精度。撞墙、路程过短、轮空转才需要重录。

### T3 bag 和后面 4.2a 的 bag 有什么区别？

| | T3 bag | 4.2a bag（待做） |
|---|---|---|
| 话题 | `/odom` `/ground_truth` `/tf` | `/cmd_vel` `/odom` `/scan` `/camera/image_raw` + `/tf` |
| 目的 | 里程计体检 | 全链路离线复盘、YOLO 调试前置 |
| 真值 | 要 p3d | 一般不要（体积大） |
