# 《基于YOLO+ROS2的智能巡检机器人仿真系统》项目执行计划

> 版本：v1.0 | 制定日期：2026-08-09 | 规划周期：10周（兼职节奏，每天2-4小时）
> 制定原则：企业研发流程（需求 → 架构 → 迭代开发 → 集成测试 → 演示验收），学习嵌入开发，不做纯课程式学习。

## 一、项目总体介绍

### 1.1 项目定位

一个**端到端可运行的智能巡检机器人仿真系统**：在 Gazebo 中构建虚拟厂区/机房场景，机器人搭载虚拟摄像头与激光雷达，通过 SLAM 建图、Nav2 自主导航执行巡检任务，YOLO 实时检测画面中的异常目标（人员闯入、烟雾、杂物堆放等），检测结果与机器人状态通过 Web 平台实时展示与回溯。进阶阶段接入大模型，实现"自然语言下达巡检指令"。

这不是 ROS2 学习项目，而是**以 ROS2 为骨架的 AI+机器人系统集成项目**。ROS2 是工具，交付物是系统。

### 1.2 技术价值（对应岗位 JD 关键词）

| 能力维度 | 本项目覆盖 | 对应岗位关键词 |
|---|---|---|
| 机器人中间件 | ROS2 节点/话题/服务/Action/TF2/launch | ROS2 开发经验 |
| 机器人算法栈 | SLAM Toolbox、Nav2、代价地图、行为树 | SLAM、自主导航 |
| AI 视觉 | YOLO 推理优化（ONNX/TensorRT）、检测+定位融合 | 视觉感知、目标检测工程化 |
| 仿真工程 | Gazebo 世界建模、URDF/xacro、传感器仿真 | Gazebo 仿真经验 |
| 系统集成 | 多节点分布式架构、rosbridge、FastAPI、数据库 | 系统架构设计能力 |
| 工程素养 | Git 分支模型、launch 一键启动、文档、演示视频 | 完整项目闭环 |

### 1.3 最终 Demo 效果（验收画面）

1. 一条命令启动：Gazebo 厂区场景 + 机器人 + 全部节点上线；
2. 机器人在地图上按预设巡检点自主巡航（Nav2 规划、动态避障）；
3. 巡航中 YOLO 实时检测：发现"禁入区人员/烟雾/消防通道杂物"→ 控制台告警 + 截图存证 + 地图上标记异常点；
4. Web 平台实时显示：机器人位姿轨迹、摄像头画面（带检测框）、巡检任务进度、异常事件列表（可回放）；
5. （进阶）输入"去3号机房看看有没有异常"→ 大模型解析为导航目标 → 机器人执行并回传检测结果。

### 1.4 简历包装方式（STAR 写法示例）

> **智能巡检机器人仿真系统** —— 个人项目 · 机器人系统集成（2026）
> - 基于 ROS2 Humble 设计分层式机器人软件架构，实现 8+ 功能节点解耦协作（感知/定位/规划/任务/Web），通过自定义消息与 Action 完成跨模块通信；
> - 集成 SLAM Toolbox 与 Nav2 实现激光建图与自主导航，调优代价地图与规划器参数，巡检任务成功率达 XX%；
> - 将 YOLOv8 检测模型以 ONNX/TensorRT 部署为独立 ROS2 推理节点，结合 TF2 坐标变换将 2D 检测框映射至地图坐标，实现"检测即可定位"；
> - 基于 FastAPI + rosbridge 构建 Web 监控平台，实时展示机器人状态与巡检事件，事件持久化至数据库支持回放；
> - （进阶）接入 LLM 将自然语言指令解析为结构化巡检任务，打通"语义→任务→导航→检测"全链路。

### 2.2 ROS2 节点设计（核心节点清单）

| 节点 | 语言 | 订阅 | 发布 | 职责 |
|---|---|---|---|---|
| `gazebo` + 传感器插件 | - | - | `/camera/image_raw`、`/scan`、`/odom`、`/tf` | 仿真环境与传感器数据 |
| `yolo_detector_node` | Python | `/camera/image_raw` | `/vision/detections`、`/vision/annotated` | YOLO 推理，发布结构化检测结果+标注图 |
| `object_localization_node` | Python | `/vision/detections`、`/tf` | `/vision/anomalies_map` | 结合 TF/深度把检测框映射到 map 坐标 |
| `anomaly_manager_node` | Python | `/vision/anomalies_map` | `/events/anomaly` | 异常判定（类别/区域/去重/置信度过滤），事件落库 |
| `patrol_mission_node` | Python | `/events/anomaly` | Nav2 Action 客户端 | 巡检状态机：按航点巡航、任务调度、断点续巡 |
| `slam_toolbox` / `amcl` | C++(官方) | `/scan`、`/tf` | `/map` | 建图模式与定位模式切换 |
| `nav2` 全家桶 | C++(官方) | `/map`、`/scan`、`/odom` | `/cmd_vel` | 路径规划、控制、恢复行为 |
| `web_bridge`（rosbridge + FastAPI） | Python | rosbridge 全量 | WebSocket/HTTP | 状态聚合 API、事件查询、实时推送 |
| `llm_command_node`（进阶） | Python | `/llm/command`（web 下发） | 调用 patrol/Nav2 Action | 自然语言→结构化任务（JSON Schema 约束输出） |

自定义接口（`inspection_interfaces` 包）：
- `msg/Detection.msg`（bbox、class、confidence、track_id）
- `msg/AnomalyEvent.msg`（类型、地图坐标、时间戳、截图路径、处理状态）
- `action/PatrolTask.action`（航点列表 → 进度反馈 → 结果）

### 2.3 数据流设计

**感知流**：`相机插件 → /camera/image_raw (QoS: best_effort) → yolo_detector → /vision/detections (reliable) → object_localization (TF查询) → anomaly_manager → 事件落库 + Web推送`

**导航流**：`/scan + /odom → slam/amcl → /map+TF → Nav2 → /cmd_vel → Gazebo 差速插件`

**巡检流**：`patrol_mission (Action Server/Client) → Nav2 NavigateToPose → 到达航点 → 触发检测快照 → 任务进度反馈 → Web`

**QoS 要点**：图像用 `best_effort + volatile`（防堆积）；检测/事件用 `reliable`；`/cmd_vel` 用默认。这是面试高频考点，也是新手高频 bug 源。

### 2.4 AI 模块设计

- **模型**：YOLOv8n/s 起步（n 保帧率，s 保精度），自训练 3-5 个巡检类别（person、smoke、fire、box/obstacle、extinguisher）；数据集用公开数据 + 仿真截图合成。
- **推理链路**：`cv_bridge → 预处理(letterbox) → ONNX Runtime / TensorRT → NMS → 结果发布`。推理与 ROS 回调分离（独立线程+队列），避免阻塞回调——这是工程化关键点。
- **检测→定位**：相机内参 + TF2（`camera_link → map`）做射线投影，落地平面求交得到目标地图坐标；仿真环境可加深度相机简化。
- **大模型层（进阶）**：LLM 只做"语义解析"（输出 JSON：目标点/区域/检测类别），**不让 LLM 直接控制底层运动**——安全边界清晰，也是面试加分点。

### 2.5 仿真环境设计

- **场景**：自建厂区世界（车间+走廊+机房+禁入区），用 Gazebo Building Editor 起步，后期加纹理与动态障碍物（行人 model 用 actor 脚本巡回）；
- **机器人**：基于 TurtleBot3 Waffle 改造（加相机云台），或自建 xacro 差速底盘 + 激光雷达 + RGB-D 相机；
- **传感器对齐**：虚拟传感器的话题名、frame_id、内参必须与后续真实机器人保持一致——仿真到实机迁移时只需换驱动包。

## 三、技术路线规划（8 阶段）

> 说明：你已会 Python/OpenCV/YOLO/FastAPI，阶段 4、7 对你主要是"ROS 接口化"，不是学新技术。

### 阶段 1：环境搭建（3 天）
- **学习内容**：Ubuntu 22.04 基础、ROS2 Humble 版本选型逻辑、colcon 构建体系。
- **开发任务**：装 Ubuntu 22.04（双系统或 WSL2 起步）+ ROS2 Humble + Gazebo + VSCode 插件；跑通 turtlesim；初始化 Git 仓库与目录骨架。
- **完成标准**：`ros2 run turtlesim turtlesim_node` 正常；Gazebo 打开官方 demo 世界不黑屏；仓库有 README 和初始 commit。
- **常见问题**：WSL2 下 Gazebo 渲染异常（装 WSLg 或转双系统/虚拟机）；国内源配置（清华/中科大镜像）；`locale` 未设置导致 colcon 报错。

### 阶段 2：ROS2 基础（1 周）
- **学习内容**：节点/话题/服务/Action/参数/launch/TF2/rclpy 生命周期；QoS。
- **开发任务**：用 rclpy 手写"发布者-订阅者-服务-Action"四个最小 demo；写一个参数化节点并用 launch 启动；用 `tf2_ros` 广播一个自定义坐标系。
- **完成标准**：能用一张图讲清本项目的 topic 清单并全部用 `ros2 topic echo` 验证；不写代码能画出 TF 树。
- **常见问题**：QoS 不匹配导致订阅无数据（图像话题必踩）；launch 中节点命名空间冲突；`source install/setup.bash` 遗忘症。

### 阶段 3：机器人仿真（1.5 周）
- **学习内容**：URDF/xacro、Gazebo 插件（差速驱动/相机/激光雷达）、ros2_control 概念。
- **开发任务**：自建差速底盘 xacro（或改造 TurtleBot3）；挂载相机+雷达并校准 frame；搭建厂区世界 v1（车间+走廊+3 个巡检点）。
- **完成标准**：机器人在 Gazebo 中可被 `/cmd_vel` 驱动；`/camera/image_raw`、`/scan` 正常发布且 RViz 可视；场景有明确巡检点位。
- **常见问题**：Gazebo 模型库下载慢（提前离线缓存 `~/.gazebo/models`）；URDF 惯性参数缺失导致机器人"抽搐"；frame_id 拼写不一致。

### 阶段 4：YOLO 视觉接入（1.5 周）
- **学习内容**：cv_bridge、image_transport、自定义消息、推理性能优化。
- **开发任务**：`yolo_detector_node`（先 Ultralytics 原生推理跑通，再切 ONNX）；发布自定义 `Detection` 数组 + 标注图；写异常判定与事件落库；自训练巡检类别模型（可先用 COCO 的 person 类跑通链路）。
- **完成标准**：仿真画面中人员/障碍物被实时框出，RViz/Web 可见标注图；事件写入数据库；帧率 ≥10FPS（CPU）/≥25FPS（GPU）。
- **常见问题**：cv_bridge 与 numpy 版本冲突；回调阻塞导致图像延迟累积（必须队列+线程）；GPU 版 onnxruntime 与 CUDA 版本对不齐。

### 阶段 5：SLAM 与自主导航（2 周）—— 本项目最难阶段，预留 buffer
- **学习内容**：占用栅格地图、SLAM Toolbox 原理、AMCL、Nav2 架构（BT、代价地图、规划器/控制器插件）、行为树。
- **开发任务**：键盘遥控建图并保存；切换 AMCL 定位；接入 Nav2 单点导航；调参（膨胀半径、最大速度、DWB 评分权重）；多航点串行导航 demo。
- **完成标准**：建出可用厂区地图（边缘闭合、无重影）；给定目标点自主到达成功率 ≥90%；RViz 中代价地图、规划路径可视化正常。
- **常见问题**：建图漂移（检查轮式里程计协方差与雷达安装位）；Nav2 启动后 `global frame does not exist`（TF 未通）；机器人原地打转（代价地图 footprint/膨胀参数错误）。

### 阶段 6：智能巡检任务（1.5 周）
- **学习内容**：Nav2 Action 接口、任务状态机、行为树定制（可选）。
- **开发任务**：`patrol_mission_node`：航点序列巡航 + 到点检测快照 + 异常联动（发现异常→悬停取证→继续巡航）；任务暂停/恢复/中止；断点续巡；巡检报告生成（JSON + 截图）。
- **完成标准**：一键下发巡检任务，全程无人工干预跑完 3+ 航点；异常事件带地图标记与现场截图；任务结束后产出结构化巡检报告。
- **常见问题**：Action goal 超时未配置导致任务卡死；导航失败后的重试/绕行策略缺失；事件风暴（同一目标重复告警——需空间+时间双维度去重）。

### 阶段 7：Web 管理平台（2 周）—— 你的主场，重点做出"产品感"
- **学习内容**：rosbridge_suite、WebSocket 推送、前端选型（Vue3 或轻量原生）。
- **开发任务**：FastAPI 后端（事件 CRUD、任务下发 API、机器人状态聚合）；rosbridge 实时转发（位姿/标注图像/告警）；前端 Dashboard（地图轨迹、视频流、事件列表、任务控制面板）；历史回放。
- **完成标准**：浏览器完成"看状态—发任务—收告警—查报告"闭环；页面不土（这是你区别于纯算法简历的地方）。
- **常见问题**：rosbridge 图像话题带宽爆炸（图像必须降分辨率/降帧率走独立话题）；跨域配置；WebSocket 断线重连。

### 阶段 8：大模型机器人控制（1.5 周，进阶）
- **学习内容**：Function Calling / JSON Schema 约束输出、提示词工程、Agent 安全边界。
- **开发任务**：`llm_command_node`：自然语言→结构化任务 JSON（目标区域/检测类别/优先级）；指令合法性校验（白名单区域、危险指令拒绝）；与 patrol 节点打通；对话式结果汇报。
- **完成标准**：输入"去 2 号车间检查有没有人和烟雾"，机器人自动执行并用自然语言汇报结果；非法指令（如"冲出地图"）被安全拒绝。
- **常见问题**：LLM 输出格式漂移（用 JSON Schema/重试兜底）；指令歧义未澄清（要求 LLM 不确定时反问）；把 LLM 接进控制回路的延迟错觉（LLM 只做任务层，不进实时回路）。

## 四、详细执行计划（10 周逐日）

> 默认节奏：每天 2-4 小时。每天三段式：**学习（30-40%）→ 开发（60-70%）→ 当日输出物**。周末可用于补 buffer。
> 每日输出物必须可验证（能运行的命令/截图/commit），不接受"我理解了"作为输出。

### 第 1 周：环境 + ROS2 核心机制

- **Day 1**：学习：版本选型逻辑（为什么是 22.04+Humble）。开发：装 Ubuntu 22.04（WSL2 起步可，建议直接双系统或虚拟机）、配国内源。输出：系统就绪截图。
- **Day 2**：学习：ROS2 安装与 colcon。开发：装 Humble + Gazebo，跑 turtlesim + Gazebo 官方 demo。输出：两个 demo 跑通截图。
- **Day 3**：学习：Git 工程规范（分支模型、commit message）。开发：初始化仓库与目录骨架、README、.gitignore。输出：首次 commit。
- **Day 4**：学习：节点/话题/rclpy 基础。开发：手写 pub/sub demo（发布模拟巡检日志，订阅打印）。输出：包 `inspection_bringup` 雏形。
- **Day 5**：学习：服务与 Action 区别。开发：手写 service（查询机器人状态）+ action（模拟任务进度反馈）。输出：两个可运行 demo。

### 第 2 周：仿真机器人 + 场景搭建

- **Day 8**：学习：URDF 结构（link/joint/visual/collision/inertial）。开发：手写差速底盘 URDF。输出：RViz 中显示底盘模型。

## 五、开发环境规划

| 项 | 选型 | 理由 |
|---|---|---|
| OS | **Ubuntu 22.04 LTS**（双系统 > 虚拟机 > WSL2） | ROS2 Humble 官方目标平台；WSL2 可起步但 Gazebo 渲染和网络多播常踩坑，只建议前 2 周过渡 |

| 视觉 | YOLOv8（Ultralytics）→ ONNX Runtime（+TensorRT 可选） | 你已有基础，重点放在 ROS 化与性能 |

| 数据库 | SQLite（起步）→ PostgreSQL（收尾迁移，简历更好看） | 先跑通再升级 |

| Git 策略 | `main`(稳定) + `dev` + `feature/*`；每阶段打 tag（v0.1-sim、v0.2-vision…） | tag 就是你的阶段验收凭证 |

## 六、硬件规划

**结论：当前阶段（第 1-10 周）不需要购买任何硬件。** 纯仿真足以交付完整项目，花的钱应该是 0 元。

唯一隐性要求：**开发机建议 16GB 内存 + 4 核以上 CPU**；NVIDIA 显卡非必需（YOLOv8n CPU 可跑 10FPS，足够仿真演示），有独显则体验更好。

若项目完成后想进阶真实机器人（这是第二项目，不是本项目的尾巴），三档方案：

| 方案 | 预算 | 配置 | 适合目标 |
|---|---|---|---|
| 零预算 | ¥0 | 纯仿真 + 把代码做成 hardware-agnostic（预留驱动抽象层） | 简历展示已够用 |
| 入门实机 | ¥2,500-4,000 | 树莓派5(8G) 或 Jetson Orin Nano + 成品 ROS2 差速底盘套件（含电机/雷达）+ USB 相机 | 验证 sim-to-real，跑通真实建图导航 |
| 标准方案 | ¥6,000-9,000 | Jetson Orin Nano Super + RPLIDAR A1/S2 + RealSense D435i + 铝型材底盘 | 可部署 TensorRT 推理，性能达标，面试可讲"边缘部署优化" |
| 不建议 | ¥15,000+ | AGX Orin / 机械臂复合机器人 | 个人项目边际收益递减，除非明确求职方向需要 |

**建议**：完成仿真项目并拿到面试反馈后，再决定是否投入实机。仿真项目 + 讲清架构 = 80% 的简历价值；实机是最后 20%，且伴随大量硬件调试时间成本。

inspection-robot/                    # Git 仓库根

│   ├── architecture/                # 架构图(drawio源文件+导出图)
│   └── weekly-review/               # 每周复盘
├── ros2_ws/                         # ROS2 工作空间
│   └── src/
│       ├── inspection_interfaces/   # 自定义 msg/srv/action（协议先行）
│       ├── robot_description/       # URDF/xacro/RViz 配置
│       ├── simulation_worlds/       # Gazebo 世界/模型/启动文件
│       ├── vision_perception/       # yolo_detector / object_localization
│       ├── inspection_mission/      # patrol_mission / anomaly_manager
│       ├── navigation_config/       # Nav2/SLAM 参数与地图（只放配置，不fork官方包）
│       ├── llm_control/             # 大模型指令节点（第9周）
│       └── inspection_bringup/      # 顶层 launch：一键启动所有
├── web/
│   ├── backend/                     # FastAPI：API/事件库/rosbridge桥接
│   └── frontend/                    # Vue3 Dashboard
├── models/                          # YOLO 权重(.pt/.onnx)与训练脚本、数据说明
├── scripts/                         # setup.sh、环境检查、rosbag 录制脚本
├── assets/                          # 演示 GIF、视频封面、README 素材
└── .github/workflows/               # (可选) CI：colcon build + lint

关键约定：
- **协议先行**：`inspection_interfaces` 第一周就建，节点间只认接口不认实现；
- **配置与代码分离**：Nav2/SLAM 只存参数 YAML，不复制官方源码；
- **launch 分层**：simulation.launch → navigation.launch → perception.launch → bringup.launch 总装；
- **数据集不入库**：大文件（权重/数据集/rosbag）用 `.gitignore` + README 说明下载方式。
