# 阶段 3.4：激光雷达 `/scan` 说明文档

> 在 `robot_v0` 上挂 Gazebo ray 传感器，发布 `sensor_msgs/LaserScan`。  
> 配套：`robot_v0.urdf.xacro`、`robot_v0.gazebo.xacro`、`lidar_test.world`

**最后更新：** 2026-08-30

---

## 1. 目标（一句话）

机器人顶上有一个红色小圆柱（`laser_link`），话题 **`/scan`** 持续出激光测距；RViz 里能看到打在障碍物上的点。

---

## 2. 数据流

```text
Gazebo ray 传感器（水平 360°，10 Hz）
        ↓
libgazebo_ros_ray_sensor.so
        ↓
/scan  (sensor_msgs/LaserScan, frame_id=laser_link)
        ↓
RViz LaserScan 显示 / 后续 SLAM（Cartographer / slam_toolbox）
```

| 项 | 值 |
|---|---|
| 话题 | `/scan` |
| 类型 | `sensor_msgs/LaserScan` |
| `frame_id` | `laser_link` |
| 更新率 | 10 Hz |
| 角度 | ±π，360 samples |
| 量程 | **0.30** ～ 12.0 m（`range_min` 以下在 `/scan` 里为 `inf`） |
| 插件 | `libgazebo_ros_ray_sensor.so`（CPU `ray`，不用 `gpu_ray`） |

**为什么不用 gpu_ray？** VMware 显卡转发下 GPU 激光经常无数据或花屏；CPU ray 稳，作品集仿真够用。真机换成实物雷达驱动即可，话题名仍可叫 `/scan`。

---

## 3. TF 树（本阶段）

```text
odom → base_footprint → base_link
                          ├── left_wheel_link / right_wheel_link / caster_link
                          └── laser_link   ← /scan 的 frame
```

## 5. 为什么要有 laser_link（分层）

| 层 | 作用 | 真机要不要 |
|---|---|---|
| 几何 link | 雷达装在哪、相对车身多高 | 要（标定外参） |
| Gazebo ray | 仿真里「假造」测距 | 仿真才有；真机换驱动 |
| `/scan` 话题 | 统一给 SLAM/避障用 | 要（标准接口） |
| `frame_id` | TF 把点变到 map/odom | 要，错了建图全歪 |

## 6. 自车红点排查链（为什么「抬高一点」不够？）

> 2D LiDAR **不是**上下全空间扫描，而是**一条水平平面**转 360°（本仓库只有 `<horizontal>`，无 `<vertical>`）。

### 6.1 直觉 vs 实际

你以为只改了一个参数「雷达高一点」，实际同时碰到四层：

```text
物理层（Gazebo）  射线撞到了谁？→ 真实距离
       ↓
数据层（/scan）   min_range 以下 → inf，不发给算法
       ↓
显示层（RViz）    点 Size → 你眼睛看到的
```

| 改动 | 在哪一层 | 干什么 |
|------|----------|--------|
| 光心 `<pose>` 抬高、去掉 `laser_link` collision | **物理** | 射线别撞雷达壳 / 车身 |
| `min_range=0.30` | **数据** | 太近的点当无效（**兜底，不是根治**） |
| RViz `Size=0.02` | **显示** | 点别画太大（**不改测量**） |

**对蓝色车身：** 扫描平面高于车顶 collision → 水平射线理论上碰不到车身。  
**你当时看到的一圈红点：** 主因往往是 **光心在红圆柱中心 + 外壳带 collision**，射线先打自己（约 3cm），不是「平面扫错了」。

### 6.2 侧视：第一版为什么自扫

```text
   ●──→──→──→  扫描平面在圆柱「肚子」（sensor pose=0）
┌──┴──┐
│红圆柱│  ← laser_link 有 collision 时，水平射线先打外壳
└──┬──┘
┌──┴──────┐
│ 蓝车身   │  车顶 z≈0.05（相对 base_link）
└─────────┘
```

修法（`robot_v0` 当前配置）：

1. **`laser_link` 只留 visual，不要 collision**
2. **sensor `<pose>`** 抬到圆柱顶 + `laser_scan_z_offset`（3cm）
3. **`min_range=0.30`** 作保险丝

### 6.3 本车扫描平面高度（心算用）

| 量 | 值（相对 `base_link`） |
|----|------------------------|
| 车顶 | z ≈ +0.05 m |
| 雷达中心 `laser_joint` | z ≈ +0.07 m |
| 光心再抬（顶面 + 3cm） | +0.05 m |
| **扫描平面** | **z ≈ +0.12 m**（比车顶高约 7cm） |

因此水平射线不应碰到蓝色方盒；若 RViz 仍像有一圈点，先查 Gazebo 蓝线（`visualize=true`）与 RViz 点大小，再以 `ros2 topic echo /scan` 为准。

### 6.4 排查顺序（不要只调一个旋钮）

```text
① 光心高度（sensor pose，不是模型看起来高不高）
② laser_link / 支架有没有 collision 挡射线
③ 扫描平面是否高于 base_link 顶面 collision
④ min_range（数据过滤，真机过大会漏近障）
⑤ RViz Size（仅显示）
```

### 6.5 一句话笔记

> 2D 雷达是一条水平线；抬高若只动 link 不动光心，或光心在带 collision 的壳里，仍会自扫。`min_range` 是数据层保险丝，RViz Size 是显示层美颜——三层别混。

### 6.6 以后 Nav2 / SLAM 还要不要改？

3.4 验收已过，**不必再动**。若以后导航要更真实：优先调 footprint / 滤波，不要盲目加大 `min_range`（会漏掉 30cm 内的真障碍物）。

## 7. 踩坑

| 现象 | 原因 | 处理 |
|---|---|---|
| `/scan` 没有 | 未重编 / 旧 Gazebo 未杀干净 | `colcon build` + `pkill -f gzserver` |
| ranges 全是 inf / max | 用了 `empty.world` 无障碍 | 改用 `lidar_test.world` |
| RViz 无点 | Fixed Frame 不对或无 TF | Fixed Frame=`odom`，确认 `/tf` |
| 自车轮廓一圈近距离点 | 雷达外壳 collision + min_range 太小 + RViz 点太大 | min_range=0.30；光心抬高；RViz Size=0.02 |
| 圆柱方向点很少 | 小目标远距离，张角只有 ~10° | 正常；加 samples 或走近/放大障碍物 |
| gpu 激光没数据 | VMware GPU | 本仓库固定 CPU `ray` |
