## 3. 关键技术栈与参数（定版）

| 项 | 值 / 说明 |
|---|---|
| 全局规划 | NavFn（GridBased），`tolerance: 0.5`，`allow_unknown: true` |
| 局部控制 | DWB，`max_vel_x: 0.15`，`xy_goal_tolerance: 0.10`（goal_checker 与 FollowPath 成对） |
| progress_checker | `required_movement_radius: **0.25**`（原 0.5，门口慢车易误触 recovery） |
| AMCL alpha1–5 | **0.05**（原 0.2；T3 证明 odom 噪声远小于 0.2） |
| costmap | local=`odom` rolling 3×3；global=`map`；inflation 0.35；footprint 0.4×0.3 |
| 自救 | behavior_server 含 **spin / backup** 等；默认 BT 失败会走 recovery |
| 任务节点 | `inspection_mission/patrol_mission_node`：NavigateToPose 链式，dwell、清图、重试 |

历史事故链（更早一次）：progress 误触 → Spin → AMCL 走廊跳变进墙 → `compute_path` 反复失败 → ClearCostmap 救不了静态层。

流程：每次 delete_entity + spawn 回充电位 (0.9,3.0) → `/initialpose` → `patrol_mission_node`

**汇总：** PASS **9/10**，FAIL **1/10**，INFRA 0。  
**稳定点：** B 腿 **10/10 recoveries=0**。  
**不稳定点：** **几乎全是 B→C**；C 即使 PASS 也常高 recovery；A 有时 rec=4 与后续 C 困难相关。

失败时典型 Nav2 日志（手测与更早复现）：

```text
GridBased: failed to create plan with tolerance 0.50
Planning algorithm GridBased failed to generate a valid path to (5.26, 4.20)
ClearEntireCostmap 反复调用仍失败
behavior_server: Running backup
```

失败窗附近手采 AMCL vs GT：位置差约 **0.1~0.3 m**（未必「进墙数米」），但 **协方差偏大（尤其航向）**。

## 5. 我们已做的加固（待复测 ×10）

文件：`ros2_ws/src/inspection_mission/inspection_mission/patrol_mission_node.py`

1. 清 costmap **同步等待**完成再发 goal（原 fire-and-forget）  
2. 发下一航点 / 重试前：用当前 `/amcl_pose` **软重锚定** `/initialpose`（略收紧协方差）  
3. 去 C 前 dwell **3.5 s**；失败重试前 dwell 2.5 s  
4. 同点最多 **3** 次尝试（原 2）

**明确未改：** Nav2 yaml 里 Spin/Backup、alpha、速度、inflation。  
**内部共识：** 不把「强制原地 360° 再规划」当默认解药（准周期走廊里 Spin 会放大 AMCL 错峰）。
