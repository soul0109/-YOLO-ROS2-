# 阶段 3.3：差速驱动说明文档

> `/cmd_vel` 控制运动，`/odom` 反馈位姿。  
> 配套：`robot_v0.gazebo.xacro` 插件、`gazebo_robot_v0.launch.py`

**最后更新：** 2026-08-30

---

## 1. 目标（一句话）

在 Gazebo 里用 **`/cmd_vel` 命令** 让机器人前进/转弯，并通过 **`/odom`** 和 **TF** 看到位置变化。

---

## 2. 数据流

```text
你发 /cmd_vel (geometry_msgs/Twist)
        ↓
cmd_vel_timeout 节点（0.5s 无新命令 → 零速度刹车）
        ↓
/cmd_vel_gazebo → libgazebo_ros_diff_drive.so
        ↓
Gazebo 物理：左右轮转速不同 → 车身运动
        ↓
发布 /odom + TF: odom → base_footprint

Gazebo 真实轮角 → libgazebo_ros_joint_state_publisher.so
        ↓
/joint_states → robot_state_publisher → 轮 link TF
```

| 话题/TF | 方向 | 含义 |
|---------|------|------|
| `/cmd_vel` | 你 → 机器人 | `linear.x` 前进，`angular.z` 转弯 |
| `/odom` | 机器人 → 你 | 位姿、速度估计 |
| `odom → base_footprint` | TF | 在地图/里程计坐标系中的位置 |

---

## 3. 阶段 3.2 为什么会「自己往前溜」？

| 原因 | 说明 |
|------|------|
| 无驱动插件 | 轮子 `continuous` 可自由转，像放在斜坡上的球 |
| 落地冲击 | spawn 从 0.05m 落下，轮子蹭地就滚 |
| 无指令时无「刹车」 | 3.2 没有差速插件锁住轮速 |

**正常**，不是 bug。3.3 加了插件 + 轮关节阻尼后，静止时应明显好转。

---

## 3.1 为什么停不下来？（根因已修）

历史上试过多种修法，**真正卡住的是下面两条**（`sync_from_share` 删文件后还会反复出现）：

| # | 根因 | 现象 | 修复 |
|---|------|------|------|
| 1 | `cmd_vel_timeout` **启动即崩溃** | launch 里有 `ParameterAlreadyDeclaredException: use_sim_time` | 不在节点里 `declare use_sim_time`，只由 launch 注入 |
| 2 | 插件话题没 remap 上 | 日志仍是 `Subscribed to [/cmd_vel]` | URDF 用 `<remapping>cmd_vel:=cmd_vel_gazebo</remapping>`（`command_topic` 标签在本版插件无效） |

**当前数据流（正确版本）：**

```text
/cmd_vel → cmd_vel_timeout（输入 system_default，输出 RELIABLE）
         → /cmd_vel_gazebo → diff_drive 插件
         → 0.5s 无新命令持续发零速度刹车
```

**自测（不用按键）：**

```bash
bash ~/inspection-robot/scripts/smoke_test_stage33.sh
```

**launch 里必须看到：**

```text
[cmd_vel_timeout]: 转发 cmd_vel → cmd_vel_gazebo（RELIABLE）...
[diff_drive]: Subscribed to [/cmd_vel_gazebo]
```

若出现 `process has died` 或仍订阅 `/cmd_vel`，先 `colcon build` 并杀掉旧 Gazebo。

```bash

```

Gazebo 在后台，**本终端**约 15 秒后出现按键说明。

| 按键 | 动作 |
|------|------|
| ↑ / W | 前进（按住持续，松手停） |
| ↓ / S | 后退 |
| ← / A | 左转 |
| → / D | 右转 |
| 组合 | 如 W+A 前进左转、W+D 前进右转（弧线） |
| 空格 | 急停 |
| Q | 退出 |

**VMware 请用 W/A/S/D**（方向键常无效）。单键或组合键只打一次日志，松手后打「停止（松手）」。

## 7. 键盘组合说明（实现要点）

**根因（VMware / Linux TTY）：** 读不到 key-up，且同时只 auto-repeat **一个键**。  
W+A 时只有 A repeat；**松开 A 后，仍按住的 W 往往不会再发事件** → 软件误判松手。

**解法（两档）：**

| 模式 | 条件 | 行为 |
|------|------|------|
| **evdev（推荐）** | `python3-evdev` + 用户在 `input` 组 | 读真实 key-down/up；按住 W+A，松 A 后 W 仍有效 |
| **TTY 回退** | 无 evdev 权限 | W/S **点一下**开始/停止；A/D 按住转弯 |

一次性配置：
```bash
bash ~/inspection-robot/scripts/setup_keyboard_evdev.sh
# 注销重登后
bash ~/inspection-robot/scripts/run_gazebo_teleop.sh --build
```

临时不重登：
```bash
sg input -c 'source ~/inspection-robot/ros2_ws/install/setup.bash && ros2 run simulation_worlds keyboard_teleop.py'
```

松手判定：evdev 看真实抬起；TTY 回退靠 W/S 再点或空格急停；`cmd_vel_timeout` 另提供 **0.5s** 中继兜底。

### 7.1 设计取舍：为什么组合键卡住这么久？

**不是差速运动学错了，是输入抽象层选错了。**

| 层次 | 你在读什么 | 典型手段 | 组合键 |
|------|------------|----------|--------|
| 文本 | 一行字符 | `input()` / stdin | ❌ |
| 终端流 | 字符 + 超时猜松手 | TTY / termios | 🟡 VMware 只 repeat 一个键 |
| **设备事件** | key-down / key-up | **evdev** | 🟢 |
| 统一输入库 | 键盘 + 手柄 | SDL2 / pygame | 🟢 以后可换 |
| ROS 现成 | 小车 teleop | `teleop_twist_keyboard` | 🟢 省事但少学习深度 |

推荐把遥控想成四层（本仓库 `keyboard_teleop.py` 已是这个形状）：

```text
键盘设备 (/dev/input/event*)
    ↓  Input Driver（EvdevBackend / TtyToggleBackend）
按键状态集 pressed = {fwd, left, ...}
    ↓  Input Mapping（独立轴叠加，不要 if W and A）
geometry_msgs/Twist
    ↓  cmd_vel_timeout（仿真集成：RELIABLE + 超时刹车）
/cmd_vel_gazebo → diff_drive
```

**可组合映射（当前实现）：**

```text
W/S → linear.x ±speed
A/D → angular.z ±speed
W+A → 两者叠加 → 左前方弧线
A+D → 角速度抵消 → 直行（left/right 互斥）
```

不要用大量 `if W and A elif ...`；差速车有效维度只有 `linear.x` 和 `angular.z`，W/A/S/D 已够验收。

**evdev 是不是项目终极方案？** 否。它是**仿真阶段键盘**的解法；阶段 7 Web、真机手柄/遥控器会换输入源，底层仍只要 `Twist` / `/cmd_vel`。简历可写：

> TTY 无 key-up 导致组合键失效 → evdev 维护 pressed-set → 独立轴合成 Twist → `cmd_vel_timeout` 转发 Gazebo。

## 9. 常见问题

**Q: 发了前进但停不下来 / 一直溜？**  
A: ① launch 里搜 `cmd_vel_timeout`，若有 `ParameterAlreadyDeclaredException` 或 `process has died`，说明中继节点崩溃，刹车链断了；② 确认 `diff_drive` 订阅 `/cmd_vel_gazebo`（不是 `/cmd_vel`）；③ 跑 `bash scripts/smoke_test_stage33.sh` 自测。

**Q: `run_gazebo_teleop.sh: No such file or directory`？**  
A: 跑了 `sync_from_share.sh` 但共享目录比 VM 旧，新脚本被删了。用 `ls ~/inspection-robot/scripts/run_gazebo_teleop.sh` 确认；没有就先别 sync。

**Q: `topic [/cmd_vel_gazebo] does not appear`？**  
A: launch 日志里 diff_drive 应订阅 `/cmd_vel_gazebo`；需 `colcon build` 并重启 Gazebo。

**Q: 组合键 W+D 中途变成纯右转 / 松 A 后 W 失效？**  
A: TTY 读不到 key-up 且同时只 repeat 一个键。已改用 **evdev**（`setup_keyboard_evdev.sh` + 重登）；见 §7。

**Q: 刚 spawn 没人按键盘，小车自己往前溜？**  
A: `cmd_vel_timeout` 若 `use_sim_time:=true`，在 Gazebo `/clock` 未跑前定时器不触发 → diff_drive 收不到零速度。launch 已改为 `use_sim_time:=false` 且启动即发零速度；`colcon build` 后重开仿真。

**Q: 模型变全白？**  
A: VMware 图形刷新问题，关掉 Gazebo 重开即可。
