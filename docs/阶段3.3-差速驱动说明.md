# 阶段 3.3：差速驱动说明文档

> `/cmd_vel` 控制运动，`/odom` 反馈位姿。  
> 配套：`robot_v0.gazebo.xacro` 插件、`gazebo_robot_v0.launch.py`

**最后更新：** 2026-08-28

---

## 1. 目标（一句话）

在 Gazebo 里用 **`/cmd_vel` 命令** 让机器人前进/转弯，并通过 **`/odom`** 和 **TF** 看到位置变化。

---

## 2. 数据流

```text
你发 /cmd_vel (geometry_msgs/Twist)
        ↓
cmd_vel_timeout 节点（0.5s 无新命令 → 零速度刹车）
        ↓
/cmd_vel_gazebo → libgazebo_ros_diff_drive.so
        ↓
Gazebo 物理：左右轮转速不同 → 车身运动
        ↓
发布 /odom + TF: odom → base_footprint

Gazebo 真实轮角 → libgazebo_ros_joint_state_publisher.so
        ↓
/joint_states → robot_state_publisher → 轮 link TF
```

| 话题/TF | 方向 | 含义 |
|---------|------|------|
| `/cmd_vel` | 你 → 机器人 | `linear.x` 前进，`angular.z` 转弯 |
| `/odom` | 机器人 → 你 | 位姿、速度估计 |
| `odom → base_footprint` | TF | 在地图/里程计坐标系中的位置 |

## 3. 阶段 3.2 为什么会「自己往前溜」？

| 原因 | 说明 |
|------|------|
| 无驱动插件 | 轮子 `continuous` 可自由转，像放在斜坡上的球 |
| 落地冲击 | spawn 从 0.05m 落下，轮子蹭地就滚 |
| 无指令时无「刹车」 | 3.2 没有差速插件锁住轮速 |

**正常**，不是 bug。3.3 加了插件 + 轮关节阻尼后，静止时应明显好转。

---

## 3.1 Ctrl+C 后为什么还一直走/转？（已修复）

| 原因 | 说明 |
|------|------|
| **插件特性** | `libgazebo_ros_diff_drive` **一直保持最后一条速度**，没有内置超时 |
| **你的操作** | `ros2 topic pub ... -r 10` 再 `Ctrl+C` = 最后一条非零速度被「记住」 |

**修复：** `cmd_vel_timeout` 用 **RELIABLE QoS** 转发到 `/cmd_vel_gazebo`（与差速插件一致）。

```text
/cmd_vel（你发的）→ cmd_vel_timeout → /cmd_vel_gazebo（插件）
                      ↑
              0.5s 没新命令 → 自动发零速度刹车
```

**手动急停（备用）：**

```bash
ros2 topic pub --once /cmd_vel geometry_msgs/msg/Twist "{}"
```

## 4. 编译与启动

### 4.0 协作方式（VM 直开）

见 [`协作方式-VM直开.md`](协作方式-VM直开.md)。**勿再跑 `sync_from_share.sh`**，用 Git 同步。

**先跑自测（无需按键）：**

```bash
bash ~/inspection-robot/scripts/smoke_test_stage33.sh
```

### 4.1 推荐：方向键一键启动

```bash
bash ~/inspection-robot/scripts/run_gazebo_teleop.sh --build
```

约 4 秒后 launch 终端出现按键说明，**保持该终端焦点**：

| 按键 | 动作 |
|------|------|
| ↑ | 前进 |
| ↓ | 后退 |
| ← | 原地左转 |
| → | 原地右转 |
| 空格 / s | 立刻停止 |
| q | 退出并刹车 |

**停止双保险：** 松键 0.2s 自动停 + 中继节点 0.5s 兜底。

启动后 launch 日志应有：`[diff_drive]: Subscribed to [/cmd_vel_gazebo]`

### 4.2 手动 launch（不用键盘脚本）

```bash
source /opt/ros/humble/setup.bash
cd ~/inspection-robot/ros2_ws
colcon build --packages-select robot_description simulation_worlds
source install/setup.bash
ros2 launch simulation_worlds gazebo_robot_v0.launch.py
```

## 5. 验收

### 5.0 方向键验收（推荐）

`bash ~/inspection-robot/scripts/run_gazebo_teleop.sh --build` 启动后：

- [ ] ↑↓ 前进后退，←→ 转弯
- [ ] 松键 / 空格 后约 0.5s 内停下
- [ ] q 退出后机器人静止
- [ ] `/odom` 有位姿变化

### 5.1 手动 topic pub（备用）

每个新终端先：

```bash
source /opt/ros/humble/setup.bash
cd ~/inspection-robot/ros2_ws && source install/setup.bash
```

#### 前进

```bash
ros2 topic pub /cmd_vel geometry_msgs/msg/Twist \
  "{linear: {x: 0.15, y: 0.0, z: 0.0}, angular: {x: 0.0, y: 0.0, z: 0.0}}" -r 10
```

Gazebo 里车身应沿前方（红轴 +X）移动。**Ctrl+C 停发后约 0.5 秒内应停下**。

### 5.2 转弯

```bash
ros2 topic pub /cmd_vel geometry_msgs/msg/Twist \
  "{linear: {x: 0.0, y: 0.0, z: 0.0}, angular: {x: 0.0, y: 0.0, z: 0.5}}" -r 10
```

应原地转圈。

### 5.3 查看 odom

```bash
ros2 topic echo /odom --once
```

`pose.pose.position` 应随运动变化。

### 5.4 查看 TF

```bash
ros2 run tf2_ros tf2_echo odom base_footprint
```

## 8. 常见问题

**Q: `run_gazebo_teleop.sh: No such file or directory`？**  
A: 跑了 `sync_from_share.sh` 但共享目录比 VM 旧，新脚本被删了。用 `ls ~/inspection-robot/scripts/run_gazebo_teleop.sh` 确认；没有就先别 sync。

**Q: `topic [/cmd_vel_gazebo] does not appear`？**  
A: launch 日志里 diff_drive 应订阅 `/cmd_vel_gazebo`；需 `colcon build` 并重启 Gazebo。

**Q: 模型变全白？**  
A: VMware 图形刷新问题，关掉 Gazebo 重开即可。
