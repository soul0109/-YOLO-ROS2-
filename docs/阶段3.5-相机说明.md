# 阶段 3.5：相机 `/camera/image_raw` 说明文档

> 在 `robot_v0` 车头挂 Gazebo RGB 相机，发布 `sensor_msgs/Image`。  
> 配套：`robot_v0.urdf.xacro`、`robot_v0.gazebo.xacro`、`lidar_test.world`

**最后更新：** 2026-08-30

---

## 1. 目标（一句话）

车头有一个小黑盒（`camera_link`），话题 **`/camera/image_raw`** 持续出 640×480 彩色图；`rqt_image_view` 或 RViz 能看到前方障碍物/箱子。

---

## 2. 数据流

```text
Gazebo camera 传感器（10 Hz, 640×480）
        ↓
libgazebo_ros_camera.so
        ↓
/camera/image_raw  (sensor_msgs/Image, frame_id=camera_link)
/camera/camera_info (sensor_msgs/CameraInfo，阶段 5 YOLO 可用)
        ↓
rqt_image_view / RViz Image / 阶段 5 YOLO 节点
```

| 项 | 值 |
|---|---|
| 话题 | `/camera/image_raw` |
| 类型 | `sensor_msgs/Image` |
| `frame_id` | `camera_link` |
| 编码 | `rgb8`（Gazebo `R8G8B8`） |
| 分辨率 | 640 × 480 |
| 更新率 | 10 Hz |
| 水平 FOV | ~60°（`1.047` rad） |
| 插件 | `libgazebo_ros_camera.so` |

**为什么 10 Hz、640×480？** VM 里 Gazebo 渲染 + 后续 YOLO 都吃 CPU；低分辨率低帧率先跑通闸门，阶段 5 再按需调高。

**朝向怎么定？** 传感器写在 `<gazebo reference="base_link">` 内，完整 pose：`-1.5708 0 -1.5708`（ROS 光学系）。**不要**只在 `camera_joint` 上写 `rpy`（URDF→SDF 合并会搞错）。详见 [`阶段3.5-相机朝向排查交接.md`](阶段3.5-相机朝向排查交接.md)。

---

## 3. TF 树（本阶段）

```text
odom → base_footprint → base_link
                          ├── left_wheel_link / right_wheel_link / caster_link
                          ├── laser_link
                          └── camera_link   ← /camera/image_raw 的 frame
```

相机装在车头略低于激光，朝 **+X（前进方向）**。Gazebo 相机默认光轴沿 link 的 **-Z**，因此在 sensor 内用标准 pose `-1.5708 0 -1.5708` 旋到朝前。

---

## 4. URDF 要点

| 文件 | 内容 |
|---|---|
| `robot_v0.urdf.xacro` | `camera_link`：仅 **visual** + 惯性，**无 collision**（与 3.4 激光同理，避免奇怪自遮挡） |
| `robot_v0.gazebo.xacro` | `<gazebo reference="camera_link">` + `type="camera"` + `libgazebo_ros_camera.so` |

关键 remap：

```xml
<remapping>~/image_raw:=camera/image_raw</remapping>
<remapping>~/camera_info:=camera/camera_info</remapping>
<frame_name>camera_link</frame_name>
```

## 7. 常见问题

### Q1：画面全黑 / 无图像

- 确认 `gzserver` 在跑：`ros2 topic hz /camera/image_raw` 应 ~10 Hz
- 头less 冒烟用 `gui:=false` 仍会有图像（离屏渲染）；若 hz=0，看 launch 日志里 camera 插件是否加载失败
- 勿同时跑阶段 2 `demos.launch` 占满 CPU

### Q2：画面是橙色圆球？

- 那是车头 **万向轮**（`caster_link`）；旧版相机 `rpy` 含 `yaw π` 或位置偏低，合并后 roll=π，光轴怼着万向轮
- 现版：车顶前缘 + `rpy="0 π/2 0"`；**必须** `colcon build` 后**完全重启** Gazebo（旧 spawn 不会热更新 URDF）

### Q3：画面方向不对（朝地/朝后）

- 旋转写在 **`camera_joint` 的 `rpy`**（`0 π/2 0`），不要只写在 sensor `<pose>` 里
- URDF→SDF 合并后 sensor 内旋转会丢；用 `gz sdf -p robot.urdf` 检查最终 `<pose>`

### Q3：冒烟 / 无 DISPLAY 时相机话题不出现

- 相机要 OGRE 渲染；**激光 ray 不需要 DISPLAY，相机需要**
- 终端无 `DISPLAY` 时：脚本会自动设 `DISPLAY=:0`（有 Xwayland 时）
- 仍失败可开 `gui:=true` 或 `sudo apt install xvfb` + `xvfb-run`

### Q4：Gazebo 里相机视锥线（绿色框）

- `visualize=true` 时 Gazebo 会画传感器视锥，**不是 bug**；关掉可把 `visualize` 改为 `false`

### Q5：与激光的区别

| | 激光 3.4 | 相机 3.5 |
|---|---|---|
| 话题 | `/scan` | `/camera/image_raw` |
| 用途 | SLAM / 避障 | YOLO 异常检测 |
| 自车干扰 | 需去 collision + min_range | 一般无「扫到自己」问题 |
| VM 负载 | CPU ray 轻 | 渲染稍重，故 10 Hz |
