# 阶段 3.5：相机 `/camera/image_raw` 说明文档

> 在 `robot_v0` 车头前保险杠挂 Gazebo RGB 相机，发布 `sensor_msgs/Image`。  
> 配套：`robot_v0.urdf.xacro`、`robot_v0.gazebo.xacro`、`lidar_test.world`

**最后更新：** 2026-08-30（GUI 验收通过；排查经验见 [`阶段3.5-相机朝向排查交接.md`](阶段3.5-相机朝向排查交接.md)）

---

## 1. 目标（一句话）

车头前保险杠有一个小黑盒（`camera_link`），话题 **`/camera/image_raw`** 持续出 640×480 彩色图；`rqt_image_view` 能看到前方障碍物/木箱，WASD 转向时画面随动。

---

## 2. 数据流

```text
Gazebo camera 传感器（10 Hz, 640×480）
        ↓
libgazebo_ros_camera.so
        ↓
/camera/image_raw  (sensor_msgs/Image, frame_id=camera_link)
/camera/camera_info (sensor_msgs/CameraInfo，阶段 5 YOLO 可用)
        ↓
rqt_image_view / RViz Image / 阶段 5 YOLO 节点
```

| 项 | 值 |
|---|---|
| 话题 | `/camera/image_raw` |
| 类型 | `sensor_msgs/Image` |
| `frame_id` | `camera_link` |
| 编码 | `rgb8`（Gazebo `R8G8B8`） |
| 分辨率 | 640 × 480 |
| 更新率 | 10 Hz |
| 水平 FOV | ~60°（`1.047` rad） |
| 插件 | `libgazebo_ros_camera.so` |

**为什么 10 Hz、640×480？** VM 里 Gazebo 渲染 + 后续 YOLO 都吃 CPU；低分辨率低帧率先跑通闸门，阶段 5 再按需调高。

**朝向怎么定？** Gazebo Classic 11 相机光轴沿传感器 **+X**。`camera_link` 与 `base_link` 同向时，sensor `<pose>0 0 0 0 0 0</pose>` 即可水平朝车头。**禁止**写 `pitch=1.5708`（会把 +X 转成 -Z 朝下）。**禁止**在 `camera_joint` 写 `rpy`。详见交接文档。

---

## 3. TF 树（本阶段）

```text
odom → base_footprint → base_link
                          ├── left_wheel_link / right_wheel_link / caster_link
                          ├── laser_link
                          └── camera_link   ← /camera/image_raw 的 frame
                                └── camera_optical_frame（阶段 5 用）
```

| 部件 | `base_link` 系位置 | 说明 |
|---|---|---|
| `laser_link` | (0.05, 0, 0.07) | 车顶，3.4 已验收 |
| `camera_link` | (0.215, 0, 0.02) | 前保险杠低位，光心离地约 0.12m |

相机低于激光扫描平面，前向 FOV 主体不被红色雷达圆柱遮挡。

---

## 4. URDF 要点

| 文件 | 内容 |
|---|---|
| `robot_v0.urdf.xacro` | `camera_link` 直挂 `base_link`；仅 **visual** + 惯性，**无 collision** |
| `robot_v0.gazebo.xacro` | `<gazebo reference="camera_link">` + sensor pose 恒等 |

关键参数：

```xml
<xacro:property name="camera_offset_x" value="0.215"/>
<xacro:property name="camera_offset_z" value="0.02"/>
```

```xml
<sensor name="camera" type="camera">
  <pose>0 0 0 0 0 0</pose>   <!-- 光轴 +X = 车头，无需旋转 -->
  ...
  <frame_name>camera_link</frame_name>
</sensor>
```

## 7. 常见问题

### Q1：画面全黑 / 无图像

- 确认 `gzserver` 在跑：`ros2 topic hz /camera/image_raw` 应 ~10 Hz
- 相机要 OGRE 渲染（`DISPLAY`）；激光 ray 不需要
- 勿同时跑阶段 2 `demos.launch` 占满 CPU

### Q2：画面是橙色圆球？

- 旧版相机位置/朝向错误，光轴怼着车头万向轮；终版已修

### Q3：画面方向不对（朝地/朝后）

- **最常见误配：** `pitch=1.5708` — 在 Gazebo Classic 会把 +X 光轴转向地面
- **正确：** sensor pose 恒等 `0 0 0 0 0 0`（`camera_link` 与 `base_link` 同向时）
- **禁止** `camera_joint` 写 `rpy`
- 改 URDF 后：`colcon build` + **完全重启** Gazebo + `gz sdf -p` 检查 + GUI 视锥
- 若朝正后方：仅可试 `0 0 0 0 0 3.14159`（yaw=π），一次只改这一处

### Q4：冒烟过了但 GUI 不对？

- 正常。冒烟只查分辨率/std，**必须** GUI 视锥 + `rqt` 前方障碍 + WASD 随动

### Q5：Gazebo 里相机视锥线

- `visualize=true` 时 Gazebo 画白色视锥，**不是 bug**

### Q6：与激光的区别

| | 激光 3.4 | 相机 3.5 |
|---|---|---|
| 话题 | `/scan` | `/camera/image_raw` |
| 用途 | SLAM / 避障 | YOLO 异常检测 |
| 安装高度 | 车顶 z≈0.07 | 前保险杠 z≈0.02 |
| VM 负载 | CPU ray 轻 | 渲染稍重，故 10 Hz |

## 9. 经验摘要（详见交接文档）

1. **Gazebo Classic 相机光轴是 +X**，别照搬「-Z + pitch 90°」教程
2. **fixed-joint lump** 会让多 visual 与 TF 脱节；装饰支架不如一体 bumper cam
3. **冒烟 ≠ 朝向验收**；阶段 3.5 必须 GUI 三终端
4. **传感器布局**：相机应低于激光扫描平面，避免 FOV 与 `/scan` 平面打架
5. 完整排查时间线见 [`阶段3.5-相机朝向排查交接.md`](阶段3.5-相机朝向排查交接.md)
